## 3.1 babariana_skin1：右下角挎包有不和谐的碎块（与
`parts_004_upperarm_L_skinned_1710` 有关）

**根因**：那个网格有**两个子网格 / 两个材质**（`part1` + `part2`，索引 306 + 30），
我们原来只用第一个材质的贴图画整块 ⇒ 第二个子网格被贴错图（棕色小块，
同一处还有一条白色斜条）。

**修法**：`unity_mesh.parse_mesh` 解析 `m_SubMeshes`；`convert_2dmodel` 按子网格
**拆成多个 Part**，各用自己材质的贴图。

**证据**：重转后"棕色小块 + 白色斜条"都消失；audrey 回归四项全 0；
主文档 **3.29**。

**状态**：✅ 已修（2026-09-16 下午）。

## 3.2 banshee_skin1：`parts_Eye_normal_3027` 表情右下角有一个小块、
`parts_Hair_acc_3057` 头上有一个奇怪的块

**根因**：sprite 的多边形比 Unity 自己的渲染网格**大一圈**（Unity 用 Tight 网格，
我们原来按矩形/轮廓近似）⇒ 把**邻近图素**（孤立小岛）也画出来了。

**修法**：sprite 网格改成**直接读精灵资产里 Unity 自己生成的网格**
（`Sprite.asset` 的 `m_RD.m_VertexData` + `m_IndexBuffer`，uv 由 `uvTransform` 还原），
`sprite_outline.py`（按 alpha 复刻轮廓）保留作兜底、四边形作最后兜底。

**证据**（本轮复核产物）：

| 部件 | 版本 | 网格来源 | 结果 |
| --- | --- | --- | --- |
| `parts_Eye_normal_76` | `_probe50_rt3` | **asset** | 顶点/索引与 Unity 逐个相同 |
| `parts_Hair_acc_64` | `_probe50_rt3` | **asset** | 同上 |
| 全角色 sprite 统计 | 16 个点名角色 | **324/324 = asset**（0 回退） | `_scratch/b3_sprite_probe.py` |

banshee 20 个 sprite 里 18 个 `dFill = 0.0000`（顶点逐位相同）；
渲染同帧比对：额头上的灰块消失、与 Unity 同帧一致。
主文档 **3.31**。

**状态**：✅ 已修（2026-09-16 下午）。

## 3.3 cerberus_skin3：脸上有不会动的多余的眉毛块 +
`Part_Eye_Smile_L_26`、`Part_Eye_Close_R_26`

也就是说：这几个件在**工程数据里就没有任何显隐/透明度动画**（不是转换器把它们

**可能的两条路**（需要你拍板，因为会改动成品外观）：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A（推荐先试） | 给这几个件加**静态屏蔽表**，或按"同层同位置只保留一组"的规则裁掉 | 需要确认哪一组是"正确的"那一组（可以用 Unity 截图对照一次） |
| B | 在转换器里做"同组互斥裁决"（同一父组下只留曲线值最高的那个） | 会影响所有角色的变体件（本轮已经把默认口径改成按关键帧，多数角色已不再重复；剩下这种"全都没有曲线"的件裁决无从下手） |

## 3.4 constantias2_skin1：眼睛和眼镜的方向是反的

**查到的实情**：

| 部件 | 贴图 | `m_FlipX` |
| --- | --- | --- |
| `face_ani_21`（脸，带眼睛/表情，**Sprite 交换**的那一件） | `P_ConstantiaS2_NS1_Smile.png` | **True** |
| `parts_glasses_11` / `parts_glasses2_19`（眼镜） | `P_ConstantiaS2_NS1_parts.png` | False |

Unity 的 `m_FlipX` 是"**绕 pivot 镜像几何**、UV 不变"（不是换 UV），
我们已经在 **3.25** 按这个语义重写过两条代码路径，并用运行时真值验证过
（alice_skin2 的伞中心/尺寸 **Δ = 0.0000**）。

所以按数据推：**Unity 里这张脸也是镜像的**，而眼镜没有被镜像 ⇒
"眼睛向左、眼镜向右"是**工程资源本身**的状态（脸这件贴图的 pivot 与 flip 组合）。
