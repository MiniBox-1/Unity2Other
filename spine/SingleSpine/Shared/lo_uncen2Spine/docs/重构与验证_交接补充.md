# 重构与验证（交接补充）

> 位置/配置的权威说明在 [自包含与位置约定.md](自包含与位置约定.md)；
> 使用说明在 [GUI与CLI使用说明.md](GUI与CLI使用说明.md)；
> 旧目录结构的路径换算见 [路径对照.md](路径对照.md)。

## 1. 两点目标，两条可检验的约束

1. **自包含**：本文件夹里的代码不依赖文件夹外的任何*代码* —— 没有会执行的写死盘符
   路径，位置一律走 命令行参数 → 环境变量 → `config\lo_uncen2Spine.json` → 兜底。
2. **行为不变**：同一角色的 Spine 产物与老项目**逐字节一致**（见 §4 的 MD5 对比）。

## 2. 目录分区（2026-10-14）

```
src\   ① 项目原代码（unity2spine + ext_lo/ext_bdone + compat + tools）
env\   ② 环境（.venv-build 独立解释器、requirements*.txt）
deps\  ③ 其他依赖（third_party 备用 skel 写出器/绑定源码、reference 第三方源码）
config\④ 设定（lo_uncen2Spine.json、per_char_env.txt）
docs\  ⑤ 文档          misc\ ⑥ 杂项（unity_side 的 C#、legacy_gui、verification 检验结果）
examples\ ⑦ 例子        dist\（打包产物）、.cache\（运行时缓存日志）
```

**项目根**靠标记文件 `.u2s_root` 认（`unity2spine/paths.py::app_root()`），
不再靠"数上级目录"，所以以后还能再挪。

## 3. 这次改了哪些代码

| 改动 | 文件 | 为什么 |
| --- | --- | --- |
| 加根标记 + 配置挪到 `config\` | `src\unity2spine\paths.py` | 目录分区后"项目根"要能自己认出来 |
| 自动检查脚本定位改走 `app_root()` | `src\unity2spine\convert\static_prefab_spine.py`（`_tool_path`） | 旧写法按"包目录上一级"猜，分区后会指错 |
| 第三方 exe 定位改 `deps\third_party` | `src\unity2spine\validate\merge_existing_spine.py` | 同上 |
| 工具"项目根"统一 `_app_root()` | 20+ 个 `src\tools\*.py` | 一次机械迁移（每条替换都带断言） |
| 子进程喂 `PYTHONPATH=<根>\src` | `src\ext_lo\lo_profile.py`、`src\tools\batch_cs_convert.py` | 代码在 `src\` 下，子进程 `-m unity2spine…` 才找得到 |
| 新增 `unity2spine/console.py` | 46 个脚本自动加头 | GBK 控制台遇到 `⇒`/`\ufffd` 会直接崩 |
| `ngui2spine` 别名改成显式注册 `sys.modules` | `src\ngui2spine\__init__.py` | 打包后靠 `__path__` 找不到子模块（冻结态踩到） |
| 日志改到 `.cache\logs\`、QC 到 `.cache\qc\` | `batch_cs_convert.py`、`batch_static_check.py` | 项目根不留 `_scratch\` |

> 迁移期间的一次性脚本放在 `.cache\_migrate\`（可删）；路径改写器
> `src\tools\deabs_paths.py` 与审计 `src\tools\scan_abspaths.py` 保留为常备工具。

**踩到的坑（都修了）**：

1. 机械改写把 `"src\tools"` 写进了**非 raw 字符串** → 运行时变成制表符
   （README 里出现 `src<TAB>ools`）。现在字符串里一律用正斜杠
   （`src/tools/...`），并用 `ast` 扫过"字符串常量里的制表符"确认只剩 TSV 分隔符。
2. `--include-package=ngui2spine` 必须显式加，否则打包版的自动静态检查起不来。
3. 打包要在 `PYTHONPATH=<根>\src` 下跑，Nuitka 才找得到 `unity2spine` 包。
