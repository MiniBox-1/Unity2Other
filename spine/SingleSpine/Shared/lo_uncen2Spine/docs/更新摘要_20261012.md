## 5 Echidna「灯光闪烁」：查清 + 已修（2026-10-12）

用户报"Echidna 的 shader 还有问题 / 灯光和 Unity 不一致"，实测结论：

1. **不是 shader**：`parts_Shadow` 材质里那套 `_AdditionalAlpha` 等自定义 shader 属性是**死的**
   （工程里 4 个自定义 shader **0 个材质引用**；221 个带该属性的材质全指内建）。
2. **真凶是 `parts_Bg_001_Skinned`（灯光层）**：逐部件对真值，36 个里**只有它差到 1303px**，
   其余 ≤35px；它的骨 `Bone_COM_Skinned/Bone_BG_Light_Skinned` 位置精确、但**世界缩放**
   在某些时刻小 1e-4。
3. **来源**：Animator 的 **Dress 层**（Additive、权重 1）永远循环
   `BR_Echidna_NS1_Lobby_Loop`（1.5s），该 clip 唯一一条曲线就是把灯光骨缩到 **0.0001**
   ⇒ **Unity 里就是"灯光闪烁"**（1.5s 周期、亮/暗各 0.75s、瞬间亮灭；真值只有
   0.00021 / 2.10851 两个取值）。
4. **我们的产物却是三角波**（跨度 0.14→1380→2→1379 缓慢胀缩）⇒ 看着像"灯在飞"。
5. **两个叠加的根因**（都已修）：① CS 世界缓存"**向上取整**"⇒ "切换前的保持帧"
   拿到的是**切换后**的值；② 保持帧的值等于前一个键、被 `deform_tol` 裁掉 ⇒
   只剩切换后的键 ⇒ 跳变被线性插值铺满 0.7s。
6. **修后**：缓存按上一步填 + `force_of` 补点强制落键 ⇒ 波形变成**方波**
   （0.30~0.74 全亮 1380.45、0.76~1.45 全暗 0.14、1.52 全亮）。
   **受影响 168 clip / 67 角色**（`_scratch\step_chars_20261012.txt`）⇒ 需重转。
   验看图：`_scratch\_echidna_check\{old,new}\`（9 个同刻渲染 + README）。
7. **相位已做成可对齐**：新增 **`U2S_LAYER_PHASE=<秒>`**（默认 0 = 叠加层与 base clip 的
   t=0 对齐）。Unity 的非 Base 层**一直在跑、跨 base 状态不变**，所以真值里那一刻的相位
   = "角色实例化后过了多久 mod 层 clip 时长"，离线转换器不可能知道。
   实测 `U2S_LAYER_PHASE=0.521` ⇒ 灯光亮/暗窗口与真值**吻合到 ≈1 帧**
   （产物 亮0.54/暗1.28/亮2.03/暗2.78 vs 真值 0.521/1.265/2.007/2.764）。
   零回归：无瞬切的角色（Cerberus NS1、Tomoe…）产物逐字节不变。
8. **待办（非阻塞）**：产物里灯光最开头有 1 帧（0.02s）的"暗"——即 deform 的参考姿态
   `setup` 与"合并后曲线在 t=0 的值"不同源，下一轮顺手核一下。
