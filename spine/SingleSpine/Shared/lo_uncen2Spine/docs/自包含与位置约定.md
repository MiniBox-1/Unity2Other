# 自包含与位置约定

## 一句话

**本文件夹里的代码不依赖文件夹外的任何*代码***：代码里没有一条会执行的写死盘符路径；
凡是要"外面"的东西（Unity 工程、真值数据、别人的渲染器），位置全部由
**命令行参数 → 环境变量 → `config\lo_uncen2Spine.json` → 内置兜底** 给出。

自检（应输出 `0 个（0 处）` 且退出码 0）：

```bat
D:\Anconda\python.exe src\tools\selfcheck.py       :: 配置 + 老路径解析 + 审计
D:\Anconda\python.exe src\tools\scan_abspaths.py   :: 只做硬编码审计（CI 可用）
```

## 1. 分区与职责（2026-10-14 重整）

| 分区 | 路径 | 里面是什么 |
| --- | --- | --- |
| ① 原代码 | `src\` | `unity2spine\`（总项目：公有转化代码 + 协议 + GUI + CLI）、`ext_lo\`、`ext_bdone\`（两个扩展库）、`unity2spine_compat\`/`ngui2spine\`（老 import 名兼容）、`tools\`（命令行工具） |
| ② 环境 | `env\` | `.venv-build\`（uv 独立解释器，打包用）、`requirements*.txt`、`README.md` |
| ③ 其他依赖 | `deps\` | `third_party\`（备用 skel 写出器 exe + spine-cpp 绑定源码 + 查看器补丁）、`reference\`（第三方转换器源码） |
| ④ 设定 | `config\` | `lo_uncen2Spine.json`（**唯一"外面在哪"的清单**）、`per_char_env.txt`（每角色口径） |
| ⑤ 文档 | `docs\` | 位置约定、使用说明、历史研究、`tq_report\` |
| ⑥ 杂项 | `misc\` | `unity_side\`（要拷进 Unity 的 C#）、`legacy_gui\`（老 tkinter GUI 存档）、`verification\`（检验结果） |
| ⑦ 例子 | `examples\` | 样例产物（lo 一个、bdone 一个） |
| — | `dist\`、`.cache\` | 打包产物 / 运行时缓存日志（都可删） |

**项目根**怎么认：从 `src\unity2spine\paths.py` 往上找带 `.u2s_root` 标记的那一层
（打包后 = exe 所在目录，标记文件随 exe 放一份）。

## 2. 位置是怎么定的（优先级从高到低）

1. **命令行参数**：`--input/--out/--assets`（CLI）、GUI 里那三个输入框；
2. **环境变量**：`U2S_CONFIG`（换一份配置）、`U2S_LO_PROJECT`、`U2S_BDONE_PROJECT`、
   `U2S_INFO_DIR`、`U2S_CSBAKE_DIR`、`U2S_CACHE`、`U2S_OLD_HOME`、`U2S_VIEWER_ROOT` …；
3. **`config\lo_uncen2Spine.json`**（相对路径按项目根展开）；
4. **内置兜底**：多数落在项目根下，缺了也不会崩。

`src\unity2spine\paths.py` 提供 `app_root()`/`cfg("a.b.c")`/`cache_dir()`；
`src\unity2spine\env.py::resolve(老路径)` 把历史代码里写死的老绝对路径翻译成**当前机器**的位置。

### 配置键 ↔ 环境变量

| 配置键 | 环境变量 | 含义 |
| --- | --- | --- |
| `unity2spine.legacy_home` | `U2S_OLD_HOME` | 老主仓（历史代码里的 `D:\VB\Unity2Spine\...` 按它解析）。默认落回项目根 |
| `unity2spine.cache_dir` | `U2S_CACHE` | 缓存目录，默认 `<项目根>\.cache` |
| `lo.assets_dir` / `lo.project_root` / `lo.out_dir` | `U2S_LO_PROJECT` … | lo 线路：Unity 工程、产物目录 |
| `lo.info_dir` | `U2S_INFO_DIR` | Unity 侧动态导出根（真值帧/位姿）：`<info>\Data\PoseFrames`、`_refshot_*` |
| `lo.csbake_dir` | `U2S_CSBAKE_DIR` | CS 烘焙中间件（`playqueue.txt` / `partdump`） |
| `lo.per_char_env` | — | 每角色口径表，默认 `config/per_char_env.txt` |
| `lo.del_dir` | `U2S_DEL_DIR` | 旧产物回退目录（默认 `D:\VB\Search\del`） |
| `bdone.assets_dir` / `bdone.project_root` / `bdone.out_dir` / `bdone.spine_out` | `U2S_BDONE_PROJECT` / `U2S_SPINE_OUT` | BdOne 线路 |
| `external.viewer_root` / `viewer_python` / `viewer_render` | `U2S_VIEWER_ROOT` | 离线渲染查看器（**只用于校验/看图**，转换本体不需要） |
| `external.ida_dir` / `il2cpp_dir` / `reverse_root` | `U2S_REVERSE_ROOT` | IDA 与 il2cpp 逆向素材（研究用） |

**换机器三步**：① 改 `config\lo_uncen2Spine.json`；② 或设对应环境变量；
③ 跑 `src\tools\selfcheck.py` 看解析结果对不对。

## 3. 哪些东西**故意**不在项目里

| 位置 | 量级 | 为什么 |
| --- | --- | --- |
| Unity 工程（`...\proj-Mobile-old`、`BdOne`） | 几十 GB | 用户的输入数据，用配置指过去 |
| `info\`（真值帧、位姿、参考图） | ~20 GB | 数据 |
| `_scratch\`（CS 烘焙中间件） | ~6 GB | 中间件 |
| 查看器 `D:\VB\Viewer\Render` | ~3 GB | 别人的工程；我们只留**补丁**（`deps\third_party\...\viewer_patch`） |
| `_reverse\`（UnityPlayer.dll / pdb / mono） | ~360 MB | 逆向素材，要带走请单独拷 |

代码里**不允许**出现这些位置的字面量；历史工具里写死的部分已由
`src\tools\deabs_paths.py` 机械改写成 `_resolve(r"...")`（取值不变，只多一层位置解析）。

## 4. Unity 侧脚本的位置约定

`misc\unity_side\` 里的 C# 要拷进 Unity 工程，那边读不了我们的 json，所以约定同一组
环境变量（两边都认）：

| 环境变量 | 谁用 | 默认（不设时） |
| --- | --- | --- |
| `U2S_CSBAKE_DIR` | `U2SPlayQueueRuntime` / `PartDataRecorder` ↔ `src\tools\bake_cs\*`、`lo.csbake_dir` | `<Unity 工程根>\_scratch\_csbake` |
| `U2S_INFO_DIR` | `ExportRoots.Root` / `TwoDModelDebugExporter` ↔ `lo.info_dir` | `<Unity 工程根>\info` |

想让"Unity 写、Python 读"对上，两边设**同一个值**，或在 json 里把
`lo.csbake_dir` / `lo.info_dir` 指到 Unity 那边的默认目录。

## 5. 编码约定（Windows 老坑）

* 脚本开头统一 `from unity2spine.console import fix_console; fix_console()`：
  编码跟随控制台代码页（65001 → UTF-8）且 `errors="replace"`，**永不因编不出的字符崩**；
* 拉子进程统一喂 `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`
  （`unity2spine.console.subproc_env()`），读回来按 UTF-8 解；
* 往文件里写日志用 UTF-8。

## 6. 内存铁律（沿用）

16 GB 机器：跑重活**前**先看可用内存（< 3 GB 就别开新的），一次只跑一个渲染/转换进程；
批量逐张跑，发现单张特别慢或内存持续上涨立刻停（`src\tools\mem_probe.ps1` 可测峰值）。
