# lo_uncen2Spine 项目介绍

**Unity 原生 2D 立绘 / 模型 → Spine 3.8 骨架**的离线转换项目：
输入 Unity 工程里的 prefab（Sprite + SkinnedMesh + Animator，可含 CS 脚本驱动的
挂件/弹簧/换脸），输出 Spine 3.8 的 `.skel`（+ `.atlas` 图集 + 查看器 `.config.json`）。

* 界面：**PySide6 GUI**（选线路 → 选输入 → 跑 → 实时日志）+ **CLI**（与 GUI 同一套协议）
* 结构：**总项目放公有转化代码**，两条线路各自一个**扩展库**（`ext_lo` / `ext_bdone`）
* 形态：源码直接跑；或用 Nuitka 打成单目录 exe（`dist\main.dist\lo_uncen2Spine.exe`）
* 自包含：代码不在本文件夹之外取任何*代码*；外部只有"用户数据 / 别人的工具"，位置写在
  `config\lo_uncen2Spine.json`

## 1. 快速上手（3 分钟）

```bat
:: 0) 看有哪几条线路
D:\Anconda\python.exe main.py --cli list

:: 1) 改位置（Unity 工程、产物目录、真值目录…），然后确认解析对不对
D:\Anconda\python.exe src\tools\selfcheck.py

:: 2) 转一个角色（lo 线路：2DModel 静态 prefab + CS 烘焙）
D:\Anconda\python.exe main.py --cli run lo ^
    --input "D:\...\proj-Mobile-old\Assets\Prefabs\2DModel_3P_Alexandra_N.uAnim.prefab" ^
    --out   "D:\...\_spine_conv_cs_port"

:: 3) 批量（读 config\per_char_env.txt 的每角色口径）
D:\Anconda\python.exe src\tools\batch_cs_convert.py --limit 3

:: 4) GUI（输入选目录 = 批量；"环境变量"框写每角色口径）
run_gui.bat
```

产物（每个角色一个目录）：

```
<角色名>.uAnim_static.skel          ← 二进制骨架（标准导出）
<角色名>.config.json                ← 查看器配置（与 .skel 同名同目录）
<角色名>.uAnim_static.atlas / _0.png ← 图集
README.md / _static_info.json       ← 自检信息（部件/混合/排序明细）
_calib\static_check.json            ← 静态检查报告（转换时自动跑）
```

**依赖方向只有一条**：扩展库 → 总项目的 `unity2spine.api`；总项目**不**反向依赖扩展库
（`discover()` 优先读 entry point，打包后按包名兜底 `FALLBACK_MODULES`）。

## 3. 两条线路（扩展库）与公有代码的分工

| | `ext_lo`（lo 线路） | `ext_bdone`（BdOne 线路） |
| --- | --- | --- |
| 输入 | NormalLocal 2DModel 静态 prefab（`*.uAnim.prefab`） | BdOne NGUI 立绘 prefab |
| 公有入口 | `unity2spine.convert.static_prefab_spine` | `unity2spine.ngui.convert_chr.convert_character` |
| 特点 | Sprite+SkinnedMesh+Animator；支持 **CS 烘焙**（DynamicBone / GlobalControl）；每角色口径；换脸（`m_PPtrCurves`）；影子/加法混合/乘法烘图集 | 多套皮肤（原皮/圣诞…）、图集重打包、逐条动画曲线 |
| 参数 | `cs`（带 CS 烘焙）、`json`（debug JSON，仅研究用） | `sample_dt`（采样步长）、`max_atlas`（图集最大边） |

扩展库各自是独立包（`pyproject.toml` + entry point `u2spine.profiles`），可以单独装：

```bat
pip install -e .          :: 总项目（含 GUI 依赖时 pip install -e .[gui]）
pip install -e src\ext_lo
pip install -e src\ext_bdone
```

## 4. 数据流（一次转换发生了什么）

```
Unity 工程                      本仓
─────────────────────────────  ─────────────────────────────────────────────
Assets\Prefabs\X.uAnim.prefab  → 解析 prefab/Animator/Mesh/Sprite（src\unity2spine\unity）
Assets 下的 .meta / 贴图       → 按 guid 找资源（索引缓存在 .cache\guid）
AnimatorController 的 clip     → 采样（帧步长 --dt，默认 0.05s）
（可选）CS 脚本影响             → cs_runtime 复刻 DynamicBone / GlobalControl 的逐帧效果，
                                 把"脚本驱动"的位移/形变烘进骨架与网格
                               → 装配 Spine 3.8 数据（骨骼/插槽/网格/动画/图集）
                               → 写 .skel（本项目原生写出器）+ .atlas + 图集 PNG
                                 + <目录名>.config.json（查看器配置）
                               → 自动跑静态检查（src\tools\static_check.py）
```

* **CS 烘焙**是本项目的重点：Unity 里由脚本（弹簧、样条尾巴、换脸、显隐）驱动的部件，
  在离线转换里要**复刻成逐帧数据**，否则产物会"静态正确、动起来不对"。
* 转换**不依赖 Unity**：只要 prefab/贴图/（可选）Unity 侧导出的真值数据在，
  Python 侧就能独立跑完（打包后的 exe 同样）。

## 5. 位置与配置（"外面在哪"）

优先级：**命令行参数 → 环境变量 → `config\lo_uncen2Spine.json` → 内置兜底**。

常用键（完整表见 [docs/自包含与位置约定.md](docs/自包含与位置约定.md)）：

| 配置键 | 环境变量 | 含义 |
| --- | --- | --- |
| `lo.assets_dir` / `lo.out_dir` | `U2S_LO_PROJECT` … | Unity 工程 Assets / 产物目录 |
| `lo.info_dir` | `U2S_INFO_DIR` | Unity 侧动态导出根（真值帧、位姿） |
| `lo.csbake_dir` | `U2S_CSBAKE_DIR` | CS 烘焙中间件（playqueue / partdump） |
| `lo.per_char_env` | — | 每角色口径表（默认 `config/per_char_env.txt`） |
| `unity2spine.legacy_home` | `U2S_OLD_HOME` | 老主仓位置（历史工具里的老绝对路径按它解析） |
| `unity2spine.cache_dir` | `U2S_CACHE` | 缓存目录（默认 `<根>\.cache`） |
| `external.viewer_*` | `U2S_VIEWER_ROOT` | 离线渲染查看器（只用于校验/看图，转换本体不需要） |
| `bdone.*` | `U2S_BDONE_PROJECT` … | BdOne 线路的工程与产物目录 |

**换机器**：改 `config\lo_uncen2Spine.json`（或设环境变量）→ 跑 `src\tools\selfcheck.py` 核对。

## 6. 约定与铁律

| 约定 | 说明 |
| --- | --- |
| 标准导出 | 只出 `.skel` + 同名 `<目录名>.config.json`；`--json` 只用于排查，别进产线目录 |
| 算法/运动 | 必须与 Unity 逐帧真值对拍（`calib_geo.py` / `compare_play_truth.py`）；**shader/观感不跟 Unity 比，交人眼** |
| 每角色口径 | 写在 `config\per_char_env.txt`（相位 / 预跑 / 死曲线部件…），批量脚本会打印 `每角色口径 …`；**每条必须自成一行开头** |
| 可回退 | 旧产物搬到 `D:\VB\Search\del\`（配置 `lo.del_dir`），不就地删 |
| 内存 | 16 GB 机器：跑重活前先看可用内存，一次只跑一个；`src\tools\mem_probe.ps1` 可测峰值 |
| 自包含 | 代码里不出现会执行的写死盘符路径；审计命令见 §8 |

## 10. 已知约束与坑（都已在代码里处理）

| 坑 | 处理 |
| --- | --- |
| Windows 控制台 GBK 编不出 `⇒`/`\ufffd` 会直接崩 | 脚本开头 `unity2spine.console.fix_console()`；子进程统一 `PYTHONIOENCODING=utf-8` |
| 代码在 `src\` 下，子进程 `-m unity2spine…` 找不到模块 | 子进程喂 `PYTHONPATH=<根>\src` |
| Nuitka standalone **不设** `sys.frozen` | `unity2spine.paths.is_frozen()`（认 `__compiled__`） |
| 冻结后 `sys.executable` 是本 exe，不能当解释器 | `ext_lo` 走**同进程**调用；工具脚本 `runpy` 同进程跑 |
| 冻结后没有 entry point dist-info | `discover()` 按包名兜底；打包带 `--include-package=ext_*` 与 `ngui2spine` |
| 本机拒绝按 `msvcp140.dll`/`vcruntime140*.dll` 直接建文件（EACCES） | 打包排除这几个名字，用 `src\tools\fix_dist_runtime_dlls.py` "临时名 + 改名"补回 |
| `numpy` 是真实依赖（开发机自带易漏） | 写进 `pyproject.toml` 与 `env\requirements*.txt` |
| 机械改写容易把 `"src\tools"` 的 `\t` 写成制表符 | 字符串里统一用正斜杠；`lint_string_escapes.py` 长守 |
