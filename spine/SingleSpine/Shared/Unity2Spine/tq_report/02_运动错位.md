## 2.1 alice_skin2：`parts_Breast_ACC_L_s52` / `parts_Breast_ACC_R_s60` /
`parts_Breast_R_Shadow_s56` / `parts_Breast_L_Shadow_s51` 与 Unity 运动不符

而我们的产物默认**一个部件一个槽位、排序值固定**（`--multi-drawable` 默认关闭：
一个部件占多层要把逐帧形变写 N 遍，重角色会膨胀到 GB 级）。

**证据**（`calib_geo` 端到端，`_probe50_rt3\alice_skin2`，times 0..3）：

| --- | --- | --- |
| `parts_Umbrella_Sprite_s32` | 0.88 | **1.756**（= 3.25 记录的"编辑器采样 vs 运行时状态机的伞"，属已知口径差异） |
| `parts_Hair_Back_s0` | 0.095 | 0.212 |
| **ACC / Shadow 四件** | — | **没进前 6**（≤0.07 世界单位） |

**状态**：🔶 **待你拍板**。可选：
1. 只给这几个件开多 drawable（`--multi-drawable` 是全局开关，需要加"按部件"的白名单）；
2. 按现在的单槽位继续用（动作里偶尔遮挡顺序不对）。

## 2.2 banshee_skin1：breast 动作时表情消失

**根因**：`m_IsActive` 的求值口径。工程里的表情件是**互补开关**，但关键帧切线是 0
（不是编辑器 Constant），按"插值 + |v|>1e-3"求值会在切换点前后各留一段 0<v<1
⇒ **该显示的没显示、不该显示的显示**。

**证据**（同一份产物，两套口径对**编辑器真值** `dynamic.json` 的差异）：
`parts_Eyebrow_normal` 真值显示 194 帧 / 我们 0 帧；`parts_Eyebrow_sed` 真值 0 / 我们 198。

**修法**：显隐默认改成**按关键帧（阶跃 + v≥0.5）**（`--active-runtime` 可切回旧口径）。

**修后证据**（`_probe50_rt3\banshee_skin1` breast）：

```text
parts_Mouth_normal  [(0.0,ON),(0.3,off),(6.067,ON)]
parts_Mouth_angry   [(0.0,off),(0.3,ON),(1.167,off),(5.317,ON),(6.067,off)]
parts_Mouth_sed     [(0.0,off),(1.167,ON),(5.317,off)]
parts_Eyebrow_normal [(0.0,ON),(0.3,off),(10.0,ON)]      parts_Eyebrow_sed [(0.0,off),(0.3,ON),…]
parts_Eye_normal    [(0.0,ON),(0.3,off),(0.7,ON),(5.7,off),(6.867,ON)]  parts_Eye_Smile 与之互补
```

一眼可见：**任何时刻只有一套表情**，且 0.3~10 s 之间一直在切换（不再"没有表情"）。

**状态**：✅ 已修（16 个点名角色全部重转，`check_clip_visibility` 16/16 一致）。

## 2.3 bheur_skin1：Lobby 有眨眼，但 Spine 只是上眼眶消失

**已定位到具体数据**（`bheur_skin1` Lobby = `2DModel_BR_Bhear_NS1_Lobby.anim`）：

```text
Bone_Close_Eye          m_IsActive  (0,0) (2.583,1) (2.733,0) (3.383,1) (3.533,0) …
Part_EyeLine_12         m_IsActive  (0,1) (2.583,0) (2.733,1) …      ← 与 Bone_Close_Eye 互补
Part_Eye_Close_L        m_IsActive  (0,1) (0.133,0)                  ← 只有开头 0.13 秒是 ON
Part_Eye_Close_R        m_IsActive  (0,1) (0.45,0)   + m_Enabled (0,1) (0.133,0)
```

也就是说：Unity 里"闭眼"靠的是 `Bone_Close_Eye` 打开——而它的两个子件
（`Part_Eye_Close_L/R`）**自己的 m_IsActive 在 0.13 s 之后就是 0**。
按现在的"父链 AND"口径，这两个子件在眨眼时**不会出现**，只剩 `Part_EyeLine_12` 消失
⇒ 正是用户看到的"只是上眼眶消失"。

**状态**：🔶 **需要一次同帧对照再决定**（这属于"工程曲线与美术意图打架"，
不能凭猜改判据）。建议下一步（命令已给）：

```powershell
# 1) 出 Unity 真值（秒）
Unity.exe -batchmode -projectPath D:\VB\Search\NormalLocal\lastOrign -quit ^
  -executeMethod ModelInspect.All -probePrefab Assets/prefabs/lo/bheur/bheur_skin1.prefab ^
  -probeName bheur_skin1 -probeStates Lobby -probeTimes 2.6,2.7 -probePpu 1280 ^
  -probeOut D:\VB\Unity2Spine\_scratch\bheur_truth -logFile D:\VB\unity_logs\bheur.log
# 2) 我们的同帧（注意 --times 是"归一化比例"：2.6 s / 时长）
D:\VB\Viewer\Render\.venv\Scripts\python.exe tools\rt_frames.py _probe50_rt3\bheur_skin1 Lobby ^
  --out _scratch\bheur_rt --times 0.2 --size 1200
```

两图脸上一比即可判定：若 Unity 眨眼时**闭眼件确实出现**，就把"子件自身曲线为 0 时
仍跟随父件显示"写成一条**显式规则**（只对 `*_Close_Eye*` 这类"父开即显示"的组）。
