## 4 2026-10-10 傍晚（收官轮）：乘法件默认"直接对图集处理"

用户指令："**默认对图集直接处理，把其他导出设定为实验性的方法，默认转换的方式不用实验性的方法。**"

| 项 | 内容 |
| --- | --- |
| 默认口径 | 乘法件（Unity `Particles/Multiply` 影子）**烘进图集**：该件 UV 矩形内 texel 改成 `rgb=0`、`α = 1−m`（`m = min(1, i.color·2·_TintColor)·tex.rgb`），槽位颜色 `000000xx`、`blend` 省略（= `normal`） |
| 为什么等价 | 普通 alpha 混合在 `src.rgb=黑` 时是 `out = dst×(1−src.a)`；令 `src.a=1−m` ⇒ `out = dst×m`，**与 Unity 的乘法逐像素等价**（因子为灰时完全等价） |
| 实验口径 | `--multiply-blend`（或 `U2S_MULTIPLY_BLEND=1`）：`blend=multiply` + 区域 `α=1`，依赖运行时/查看器的 multiply 混合。**默认不用它** |
| 受影响范围 | 157 里只有 **25 个**角色用非普通混合（`shader_usage_inventory.py` 判定），**已全部重转**；其余 132 个角色的图集是源贴图逐字节复制、路径未改 |
| 账本 | `_static_info.json` 的 `multiply.parts` 记 `factor / page / rects(闭区间) / uvMap / pageSize`，校验器按账本逐条核验（不再靠 UV 反推，避免 1px 误判） |
| 新工具 | `tools\check_multiply_bake.py`（口径验收）、`tools\package_mul_review.py`（打包成给人肉眼看）、`batch_cs_convert.py --exact-file`、`shader_usage_inventory.py --out-txt` |
| 验收 | 产物 **0 个** `blend=multiply`；乘法件矩形 `rgb_max=0`、α 0~255（样例 May_NS3：α 均值 157.1 / 78.2）；逐页比对**矩形外 0 像素**被改（改动 65649 = 矩形面积 277×237）；`skel ≡ json` 仍 `max\|Δ\|=0`；25/25 角色静态检查四项全 0 |
| 同轮修的真 bug | `_bake_rects` 用了**开区间**切片，比账本矩形少烘 1 行 1 列 ⇒ 乘法件边缘留 1px 浅粉接缝（加色件老路径同样有）。改闭区间后改动像素数**等于**矩形面积 |
| 交付 | `D:\VB\Search\New\_Spine待检查_20261010_乘法烘图集\`（25 个角色 + README，**给用户肉眼看**） |
| 详见 | 交接文档 **§5.1.8 / 约束 20、29**；进展文档 **§25** |
