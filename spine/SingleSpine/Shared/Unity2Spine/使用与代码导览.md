## 0. 一句话

把 Unity 工程里的 **2DModel prefab**（`SpriteRenderer` + `SkinnedMeshRenderer` + `Animator`）
**离线**转成 **Spine 3.8**（`Root` 骨 + 每部件一个 mesh + `deform` 时间线），
并给出可复现的校验闭环。**只用磁盘静态资源**；Unity 里导出的
PoseFrames / PlayFrames / `_refshot_*` **只做校准，不进成品**。

一个角色的产物（`_probe50_rt4\<角色>\`）：

| 文件 | 作用 |
| --- | --- |
| `<角色>_static.json` | 骨架（1 根 `Root` 骨 + 每部件一个 slot/mesh + deform 时间线） |
| `<角色>_static.skel` | 同一份数据的二进制；**查看器优先读它**（快 7 倍、内存 1/15） |
| `<角色>_static.atlas` + `_0.png`… | 图集（加色件单独一页） |
| `_static_info.json` | 对账手册：prefab/scene/clip/dt/units/origin/flipX/partsMeta… |
| `.config.json` / `README.md` | 查看器配置 / 可读摘要 |

## 2. 常用操作：想干什么 → 抄哪条

### 2.1 转换

```powershell
# 单个角色（自带静态检查；-skel 同时写二进制）
python -m ngui2spine.static_prefab_spine `
  "D:\VB\Search\NormalLocal\lastOrign\Assets\prefabs\Change50\bheur_skin1.prefab" `
  _probe50_rt4\bheur_skin1 `
  --assets "D:\VB\Search\NormalLocal\lastOrign\Assets" `
  --scene  "D:\VB\Search\NormalLocal\lastOrign\Assets\Scenes\save.unity" `
  --skel --no-face-check
# 期望结尾：[static_check] 场景渲染器 N / 导出部件 M / … 全部 0

# 批量（--jobs 是内存乘数，大角色只开 1~2；先跑 --limit 试点）
python tools\convert_all_2dmodel.py --prefab-dir "...\Assets\prefabs\Change50" `
  --out _probe50_rt4 --jobs 2 --scene "...\Assets\Scenes\save.unity"

# 老产物补二进制（改了 JSON 必须补，否则查看器还在读旧 .skel）
python tools\write_all_skel.py _probe50_rt4 --force
```

常用开关（`python -m ngui2spine.static_prefab_spine --help` 有全量说明）：
`--units px|world`（默认 px，按原图尺寸 1:1）、`--pma`（全局预乘）、
`--no-secondary-anim`（不合并副 Animator）、`--multi-drawable`（默认关，实测否过）、
`--animated-only/--no-animated-only`、`--skip-texture`、`--place X,Y`。

**导出设定（2026-10-10 定稿，别乱动）**：标准导出**只出 `.skel`**（`.json` 只在 `--json`
时写、仅 Debug/研究用）；查看器配置名 = `<产物目录名>.config.json`；
**乘法件默认"直接对图集处理"**（烘成 `黑 + α=1−m`、槽位 `normal`，不依赖运行时的
multiply 混合）；`--multiply-blend`（或 `U2S_MULTIPLY_BLEND=1`）是**实验口径**
（`blend=multiply` + 区域 α=1），默认路径不用它。详见
`D:\VB\Search\New\Mobile-old_Spine转换_交接文档.md` §5.1.8 / 进展 §25。

## 3. 代码导览

### 3.1 转换库 `src\unity2spine\`（真实现，按功能分）

| 文件 | 干什么 | 什么时候动它 |
| --- | --- | --- |
| `convert\static_prefab_spine.py` | **主转换器**（16 万字符，全项目最重要的一份）：静态 prefab/场景实例 + Mesh/材质/Sprite/动画 → Spine 3.8 JSON + atlas + `.skel`；含采样、显隐、排序、deform 生成、静态检查 | 绝大多数"转换规则"改动都在这里 |
| `convert\convert_2dmodel.py` | 老的 2DModel 入口；同时提供**共用几何工具**：`load_character`、`_asset_path`、`_skin_mesh`、`_world_matrices`、`sprite_part_mesh`、`build_character_model`、`convert()` | 改几何/蒙皮口径时 |
| `convert\frame_baked.py` | 帧烘焙路线：把 Unity PoseFrames 的逐帧顶点烘焙成 Spine 动画（历史路线，非当前主线） | 只在追旧产物时 |
| `convert\single_frame_spine.py` | 单帧（t0 真值）→ Spine，用于"只要一张静态图"的场景 | 少用 |
| `unity\unity_2dmodel.py` | 解析 2DModel prefab：Transform 层级、渲染器、材质、Animator/Controller、层（`parse_animator_layers`）、主 Animator 选择 | 解析层规则（多层、去重） |
| `unity\unity_anim2d.py` | AnimatorClip（`.anim` 文本）曲线解析 + 采样（`AnimSampler`、`euler_to_quat`、`trs_mat`、`quat_to_euler`） | 姿态/插值不对时 |
| `unity\unity_mesh.py` | Mesh(`.asset`) / Sprite(`.asset`) 解析 + 矩阵工具（`mat4_vec`、`mat4_invert`…） | 网格/精灵口径 |
| `unity\unity_parse.py` | 通用 Unity 文本资源加载（`load_unity_docs`，处理多文档 YAML） | 读新类型的 `.asset` 时 |
| `spine\spine_out.py` | Spine 3.8 输出：JSON/atlas 文本、`write_viewer_config`（`.config.json`） | 改产物格式/图集 |
| `spine\spine38_binary_writer.py` | **JSON → `.skel`** 二进制写出器（可 `--verify` 回读校验） | 改二进制结构 |
| `spine\spine38_binary.py` | `.skel` 读取器（校验/审计用） | 同上 |
| `spine\sprite_outline.py` | 没有网格时按 alpha 复刻精灵轮廓（Tight 网格兜底） | 轮廓/碎片问题时 |
| `ngui\*` | **NGUI 路线**：`bdone_spine`（**当前实现**，见下）、`ngui_model` 读 prefab、`ngui_anim` 采样 Legacy 动画（含 `m_EulerCurves`）、`pack_images` 重打包图集、`spine_out` 出 Spine、`convert_chr` 是**薄壳入口**、`merge_char`/`extract_unity_spine` 合并多个 SkeletonAnimation | 接 NGUI 那类角色时 |
| `tools\convert_bdone.py` | **BdOne 全量转换**（NGUI + Legacy 动画 → Spine 3.8）：`python tools\convert_bdone.py --out _bdone_spine`，产物一个服装一个目录（json/skel/atlas/png/config + `_bdone_info.json`）；口径与校验见 `docs\BdOne_NGUI_转化.md` | 转 BdOne 那批角色 |
| `validate\validate_spine.py` | 产物自检（结构 + Spine 3.8 读取规则一致性） | 加新校验项 |
| `validate\merge_existing_spine.py` | 把 prefab 里**多个已有的** SkeletonAnimation 合成一个 Spine | 合并需求 |

## 9 2026-10-12：算法侧结案（弹簧链已逐粒子精确）

上一轮遗留的"头发还差 21.9px / 逐顶点最大 50.7px"**不是转换器的错**，是**对拍口径**问题。
三个关键结论（详见交接约束 39/40/41、进展 §35、`更新摘要_20261012.md`）：

1. **真值一律按"真实时间"录**（≈35fps，dt 0.008~0.097 随机）：历史 Play 真值一直如此
   （`U2SFrameDump.Awake()` 读 `fixedFramerate` 时队列还没 `Set`，`Time.captureFramerate`
   从未生效）；**也不能**去固定它 —— 本工程 `Animator.m_UpdateMode = 2`（**UnscaledTime**），
   固定帧长会让"时间轴"和"动画"走两个速率（实测 0.709×，`bone_head` 的最贴时刻漂到 −1.43s）。
   要步长一致就在**转换器侧**用真值的 dt 序列（`t_db_pre.py --usedt truth`）⇒ Cerberus
   头发骨 **323px → 0.008px**。
2. **`dump_db_particles.cs` 一次只跑一条链**（`dbdump.txt` 里写 `db=<名字>`）：它的
   `frames` 循环嵌在 per-db 循环里、每帧又推进**所有**链 ⇒ 第 2 条链的"帧 0"其实已经
   跑了 150 步（Alexandra `Breast` 那个假 bug：帧 0 差 28px、最大 78px）。
3. **验收弹簧链首选 `_scratch\_probe\t_db_particles.py`**（`AnimationMode` + 固定 1/60 +
   一次一条链）：先按**名字+父索引校验整条粒子树**，再比 `pos/prev/骨位/target/n`。
   实测 Alexandra `Hair` 最大 **0.003px**、`Breast` **0.0018px**、Cerberus `Hair` 中位
   **0.0004px**（最大 2.8px，只在最快摆动几帧）⇒ **树/参数/积分/输出逐项精确**。

同轮新增的体检工具：`t_db_pre.py`（Play 真值对拍，带 `--usedt/--pre/--fields/--setup/--shift`
口径开关）、`t_timemap.py`（真值**时间轴**体检：最贴时刻应恒为 0）、
