# 06 使用说明（转换器）

日期：2026-11-06
适用：`D:\VB\Convert\Live2d` 当前版本（P1–P5 流水线）

## 1. 前置

| 项 | 值 |
| --- | --- |
| Python | 3.11+（本机 3.13.9，`D:\Anconda`） |
| Unity 源工程 | `D:\VB\Search\New\归档-proj-Mobile-old\proj-Mobile-old`（只读，不会被修改） |
| Live2D Core | `D:\VB\Convert\Live2d\Cubism\Plugins\Windows\x86_64\Live2DCubismCore.dll` |
| 第三方库 | `tools\vendor\py-moc3`（MIT，已内置） |

不需要 Unity 编辑器，也不依赖 Cubism Editor。

## 2. 单角色

```powershell
cd D:\VB\Convert\Live2d
python tools\convert_batch.py --names 2DModel_3P_Alexandra_N
```

产物在 `Products\<角色名>\`：

```text
<Name>.moc3                模型（v1，Core 校验通过）
<Name>.model3.json         清单（Moc / Textures / Motions / DisplayInfo）
<Name>.cdi3.json           参数与部件的可读名
textures/texture_00..NN.png  图集页（按部件引用）
motions/<State>.motion3.json 动作（每个 Animator 状态一段）
manifest.json              转换报告（一致性、误差、段数、动作、曲线数）
```

## 3. 批量

```powershell
python tools\convert_batch.py --limit 200        # 全部 uAnim 角色
python tools\convert_batch.py --limit 3          # 前 3 个（冒烟）
```

汇总报告：`Products\_batch_report.json`（成功/失败、耗时、每角色段数与动作数）。

## 4. 校验

```powershell
# 全量：moc3 一致性 + model3/motion3/cdi3 schema + 纹理下标 + 曲线 id
python tools\validate_products.py
```

输出 `Products\_validate_report.json`；控制台给出总包数、部件/参数/动作总数。

## 6. 命名与坐标约定

| 项 | 约定 |
| --- | --- |
| 参数 | `P_<骨骼名>_<tfid后6位>_Rz`，范围 -30..30，默认 0 |
| 部件 | `Part_<序号>_<源部件名>_<骨骼名>`（≤64 字节） |
| 变形器 | `D_<骨骼名>_<tfid后6位>` |
| 坐标 | 模型空间 Y 向上；顶点以画布中心为原点；ppu = 1000 |
| UV | Unity v 向上 → 写入时 `v' = 1 - v`（moc3 UV 原点在左上） |
| 角度 | Live2D 正角度 = 顺时针，参数 = `-Unity Δz` |

## 7. 已知限制

1. **分块硬切**：跨骨三角形按多数票整块归属，边界可能出现细缝
   （`pipeline(overlap_edges=True)` 可把跨骨三角形复制到两侧填缝，默认关）。
2. **没有 Warp 残差**：分块后仍在块内做刚体，单个块内的非线性形变
   （如肘部弯曲）无法表达；P4 v2 待做。
3. **Unity 编辑器未实测**：本机 Unity 为 2021.3/2022.3，SDK 5-r.5 要求
   Unity 6000 + URP。
4. **动作来源于 Animator 状态**：每层/加性混合未单独实现，直接采样
   controller 里各状态的 clip。

## 8. 复现性

同一输入重复构建，`moc3` 与 `motion3` 的 SHA256 完全一致（已验证）。
