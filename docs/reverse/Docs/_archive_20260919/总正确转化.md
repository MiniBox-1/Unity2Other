# 总正确转化（"怎样才算转对了" + 命令 + 校验）

更新：2026-09-17。这份讲**当前唯一在用的路线**（A 路线：静态 prefab → Spine 3.8）
的规则、落点、命令与验收口径。历史踩坑见 `历史问题与修复.md`，
当前未闭环见 `现状与问题.md`。

## 1. 目标与产物契约

一个角色一个目录（`<产物根>\<角色>\`），里面：

| 文件 | 内容 |
| --- | --- |
| `<角色>_static.json` | Spine 3.8 JSON：1 根骨 `Root` + 每部件一个 slot/mesh + `deform` 时间线（逐帧形变已经把蒙皮烘进去） |
| `<角色>_static.skel` | 同一份数据的二进制骨架（查看器/运行时**优先读它**，也更快更省内存） |
| `<角色>_static.atlas` + `_0.png[, _1.png…]` | 图集（按用到的贴图打包；加色件单独一页 `_add`） |
| `_static_info.json` | 对账用手册：`prefab/scene/clip/setupClip/dt/units/unitScale/origin/flipX/pma/excludedParts/spriteSwap/relativeLayers/partsMeta` |
| `.config.json` / `README.md` | 查看器配置 / 本次导出的可读摘要 |

单位与坐标：默认以**源图像素**为单位（`units:"px"`，`1 单位 = 1 像素 = 1/675 世界单位`
由 `px_per_unit` 记录），`origin` 是 Unity 世界的贴图原点；加色部件的贴图按 alpha
预乘，普通 slot 走 `SrcAlpha/OneMinusSrcAlpha`，加色 slot 走 `ONE/ONE`。

## 2. 数据流（五步）

```
prefab/场景 ─解析─> 层级+TRS+SpriteRenderer/SkinnedMeshRenderer+材质
      │
      ├─ 选主 clip（默认 lobby 一类的待机；setup 姿态 = 该 clip 的 t=0 采样）
      ├─ 逐帧：clip 曲线求骨骼局部 T/R/S → 世界矩阵 → 蒙皮/静态顶点
      │        （蒙皮结果写成该部件的 deform 关键帧；几何完全来自磁盘数据）
      ├─ 绘制顺序：按 (sortingOrder 取整, 同值内次序) 排槽位
      └─ 显隐/颜色/形变/贴图交换 → slot attachment / color / deform 时间线
产物 ─写─> JSON（+ 可选 .skel）+ 图集 + _static_info.json
```

## 3. "正确"的规则清单（每条都是修出来的）

| # | 规则 | 一句话根因 | 代码落点 |
| --- | --- | --- | --- |
| 1 | 世界矩阵 `M = T·R·S`（按列缩放） | 旧实现写成 `T·S·R`，非均匀缩放+旋转时朝向/位置全错 | `unity_anim2d.trs_mat` |
| 2 | 蒙皮 blend 索引两种编码都要认 | 同一 format 可能是整数也可能是 float 位模式 | `unity_mesh` / `convert_2dmodel` |
| 3 | 曲线 path 折行要拼回去 | Unity 序列化超长路径会换行续写，截断会绑错节点 | `unity_anim2d._read_path_field` |
| 4 | **`path_0x…` 哈希路径要还原** | 打包过的 clip 把路径换成 `CRC32(相对宿主路径)`；不还原这些 `m_IsActive`/位姿曲线直接被丢掉 | `static_prefab_spine.path_hash / hashed_path_table / resolve_clip_paths` |
| 5 | Sprite 的渲染网格**直接读精灵资产**（`m_RD`），alpha 轮廓只做兜底 | 自己按矩形/轮廓近似会画出邻近图素（"头上/脸上碎块"） | `unity_mesh.sprite_mesh_from_sprite` / `convert_2dmodel.sprite_part_mesh` |
| 6 | 多材质网格按 **submesh** 拆成多个部件 | 只用第一个材质贴图 ⇒ 第二个子网格整块贴错图（"棕色小块"） | `unity_mesh.parse_mesh` + `convert_2dmodel` |
| 7 | 没有 `m_Enabled` 曲线时回落到渲染器**静态** `enabled` | 编辑器助手贴图（BoneJoint/IKControl/splineControl…）会画成"圆环/针" | `part_visible` + `--skip-texture` 屏蔽表 |
| 8 | 显隐按**运行时口径**：插值 + `|v|>1e-3`（不是 `v≥0.5`） | 反汇编 + 同版本实测；阶跃口径会整段藏掉只在插值窗口出现的件 | `USE_RUNTIME_ACTIVE=True`（`--active-step` 只用于对拍） |
| 9 | 颜色时间轴**保保持段**（共线才丢帧） | 去重过头 ⇒ 部件整段半透明 | `color_timeline` |
| 10 | 一个 controller 挂两个 Animator 时按 `(controller,state)` 去重，留部件树更大的宿主 | 否则每个动作导两份、且各只驱动一部分 | `enumerate_clips` |
| 11 | 副 Animator 的 clip path 相对**它自己的宿主**；副 Animator 的层默认 clip 要合并 | 用名字 `find/rfind` 会串台；不合并就丢第二层动画 | `rel_path_in` / `compose_layers` |
| 12 | 绘制顺序 = **`(sortingOrder 取整, 同值内 −层级DFS序)`**：同值内 **DFS 序小的画在上面**。反汇编侧比较键是 `u32(层+顺序) → u16(renderQueue) → float(深度) → CompareSortingGroupData → 稳定化字段`，且 `renderQueue ≤2500 / >2500` 是两套列表分开排 | 用 Unity 自己的 `Renderer.sortingKey`（反射读）实测：**5,012 条非并列关系 100% 由 (key, 深度) 解释、0 条反例**；43 条真并列里 36 条支持"DFS 倒序"。决定性案例 = `cerberus_skin1` 睁眼。落地：`slot_key_with_rank`（`rank → -rank`） |
| 12b | **同 `sortingOrder` 内的真并列，还要再分两种**（2026-09-18 晚实测 + 反汇编）：**兄弟**（不同父）按 12 条（DFS 小的在上）✓；**直系父子对要反过来**（父先画、子在上面） | 反汇编 `RenderObjectSorter`@`0x180440CC5`：排序键之后还有 **3 级未建模** tie-break（`[entry+0x1C]`、`[obj+0x0C]`→`[obj+0x08]`、`[obj+0x1C]>>1`），且两组件的所有**可导出字段完全相同** ⇒ 只靠导出数据分不出，只能按实测的等价规则做。banshee 手腕"硬边黑线"就是这个（我们父在上、Unity 子在上）。**待实现**：`slot_key_with_rank` 加"父子对反转"；细节见 `渲染顺序_反汇编研究.md` 6c |
| 13 | 同 order 内"相对层级会变"的部件才需要多 drawable；默认关闭 | 一部件多槽位要把逐帧形变写 N 遍，重角色会爆到 GB 级 | `relative_layers` / `expand_layers`（诊断用） |
| 14 | 大产物必须同时写 `.skel` | 查看器优先读二进制：同产物 JSON 路径 >10 GB，skel 路径 0.6~0.8 GB | `--skel` / `tools\write_all_skel.py` |
| 15 | `.atlas` 文件**末尾要有一个换行** | 多页 atlas 若在最后一行属性处直接 EOF，spine-cpp 3.8 解析越界读 ⇒ 一加载就 `0xC0000005`（"动不了"） | `spine_out.atlas_text()` 结尾 `+ "\n"` |
| 16 | `m_Bones` **非空但全是空引用**的 `SkinnedMeshRenderer` 一个像素都不画，必须排除 | Unity 蒙皮矩阵为空 ⇒ 顶点塌成一点；但渲染器仍 `isVisible`、`bounds` 照报，导出脚本/四层校验都看不出 ⇒ 会多出"飘在身外的头发 / 叠在眼睛上的表情层" | `static_prefab_spine` 的 `kept` 循环 `p.kind=="skinned" and p.bones and not any(p.bones)`；`tools\static_check.py::_renderer_reason` 同步口径。⚠️ `m_Bones: []`（空列表）**不**在其中，Unity 照常渲染（arman 的眼镜/红晕） |
| 17 | **同名孪生节点：曲线只绑"第一个"** | Unity 的绑定键 = **路径 + 同名序号**，同路径的第二个节点保持 prefab 姿态；我们按路径字符串一对多绑定 ⇒ 多画一件（`brownie_skin1` 左手；banshee 手腕那条**不是**这个，见规则 19） | ✅ 已实现 `dedupe_anim_paths`（按 DFS 序只绑第一个）+ 校验器读 `partsMeta[].bound` |
| 19 | **同一份网格被多个 `SkinnedMeshRenderer` 共用、而 `m_Bones` 长度不一致时，用"最长的那份骨骼表"**（= 网格 bindpose 数那份） | Unity 侧蒙皮用的是"槽位→bindpose/骨骼"两组索引表（`SkinnedMeshRendererManager::CalculateSkinningMatrices`@`0x180528240`），不是按 `m_Bones` 下标硬配；我们按 `m_Bones[k]` 硬配 ⇒ banshee 父件把权重索引 2 对到 `Bone_Finger_R1`（权重 0.6~0.81）整块被撑大、盖住手心（真值 `PoseFrames` 证明父/子同形，误差 0.2526→0.0323） | ✅ 已实现：`convert_2dmodel.build_character_model` 末尾按 `mesh_path` 分组、长表覆盖短表（长度一致的件不受影响）；细节见 `历史问题与修复.md` 第 10 节 |
| 18 | **逐帧排序**：`m_SortingOrder` 是可动画属性 | Unity 逐帧按它排序（`SetBoundCurveFloatValue` case 10 = SortingOrder）；我们把排序烘成静态 slot 顺序且 `multiDrawable` 默认关 ⇒ 该压在上面的件被盖住（draculina"抓绳子"的手看不见；`_static_info.json` 里 `multiCount: 69`） | **待修**：把逐帧排序写成 Spine 3.8 的 **`drawOrder` 时间轴**（`animations.<动画>.drawOrder`），而不是开多 drawable；现成入口 `static_prefab_spine.draw_order_timeline()` |

## 6. 用真值前先做四个体检（否则会追错方向）

1. **场景 ≠ prefab**：参考帧是从**场景实例**采的，场景里的 `m_IsActive` 可能被
   人/运行态改过（实测 `draculina_skin1` 多开 10 个节点、`constantias2_skin1`
   关掉了 `face`）。先跑：

   ```powershell
   python _scratch\scene_flags.py <Assets>\Scenes\2.unity _scratch\_scene2_flags.json
   python _scratch\scene_vs_prefab.py _scratch\_scene2_flags.json <角色…>
   ```

2. **别采到 clip 时长之外**：超出时长的时刻状态机已经切走（brownie breast 只有 2.5 s）。
3. **别信状态的第一帧**：`Play(state,0,0)` 后两帧内还在和进入 Play 的默认状态混合。
4. **PoseFrames 的 t=0 可能没应用 pose**（BakeMesh 时机），顶点会出现 `-1010/-3637`
   这种垃圾值 ⇒ t=0 不作为判据（用 t≥0.05）。

另有两条数据常识：**同名孪生节点**（同一父节点下路径完全相同的两个对象）在 Unity 里
曲线只绑第一个，对账时要按"同一路径有没有任一可见"判；**`ModelInspect` 的
`dynamic.json` 不能当显隐真值**（它不随动画变化）。

### 8.2 Unity 批处理：ModelInspect（一条命令看一个角色）

### 8.2b 渲染顺序（谁盖谁）：`ExportDrawOrder.cs`（**菜单，不是 batchmode**）

Play 模式的排序只能实测（同 `sortingOrder` 时按提交顺序画，没有公开 API 可读）。
脚本在 `Assets\Editor\ExportDrawOrder.cs`，参数**硬编码**在 `ExportDrawOrderPlan`：

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `Names` | 角色根物体名；`"*"`=场景里全部 | **`*`** |
| `OnlyInactive` | `"*"` 时只取**当前 inactive** 的根（场景里摆着没启用的那批，当前 50 个） | `true` |
| `ActivateBeforePlay` | 旧的"进 Play 前把所有目标全部激活"；默认关（改成一个一个来） | `false` |
| `ActivateInactive` | 逐个目标：激活它 → 采样 → **立刻关回 inactive** | `true` |
| **`TouchMode`** | **`observe`**=**完全不改场景**，等游戏自己把角色显示出来再采（画面=直接 Play 的样子）；`force`=脚本自己激活+强开渲染器 | **`observe`** |
| `ObserveTotalSeconds` / `IsolateFrame` | observe 的总时限 / 主帧是否也隔离（false=主帧就是 Play 画面） | `900` / `false` |
| `InstantiateMissing` / `PrefabDir` | 名单里的名字场景里没有 → 从 prefab 临时实例化（采完销毁） | `true` / `Assets/prefabs/Change50` |
| `States` | 状态名（逗号分隔）；**留空 = 全部状态** | **`""`（全状态）** |
| `Times` / `TimesRelative` | 采样时刻 / 是"归一化比例"还是"秒" | **`0.05,0.25,0.45,0.65,0.85`（5 个点）** / `true` |
| `PairScope` | `tie`=只测并列组；`all`=所有重叠可见对（完整顺序，n² 慢）；`off`=只导信息 | `all` |
| `PairCap` | 单帧成对实测上限（超了按「同并列组优先」截断） | `800` |
| `PairPpu` / `WriteImages` / `SaveFramePng` / `ExitAfter` | 实测分辨率 / 写隔离图 / 写每帧 PNG / 采完退 Play | `384` / `false` / `true` / `true` |

**退出 Play 会自动停**：`playModeStateChanged(ExitingPlayMode/EnteredEditMode)` + 每个
yield 点都会检查 `EditorApplication.isPlaying`；停止时 `Dispose()` 协程跑完各目标的
`finally`（还原 activeSelf/enabled），日志写 `[draworder] 已停止（原因）`。

> ⚠️ **量级要对一下**：`Names="*"` + 全状态 + 5 时刻 ≈ **上千~几千帧**；每帧 1~3 s
> （`PairScope="all"`）⇒ 可能**几十分钟到几小时**，还会写 1000+ 张 PNG（约 0.5~1 GB）。
> 脚本在开始前会打一行 `[draworder] 预检：…共 N 帧…约 X 分钟`，先看那行再决定要不要减量
> （`States` 写具体状态 / `Times` 少几个 / `PairScope="tie"` 或 `"off"` / `SaveFramePng=false`）。

**`Names="*"` 只取"角色根"**：候选是"场景里任意带 Animator+Renderer 的 GameObject"，
但脚本会丢掉**祖先也在候选里**的那些（`size_root`/`ch_root`/`bone_*_wing`/`GameObject`…），
否则导出真角色时会把"其它目标"（其实是它自己的子节点）整根关掉 ⇒ 采到全空帧
（2026-09-17 16:41 那次 842 帧就是这么废的，见
`_archive_20260917\交接_20260917_晚.md` 9.1）。
正常帧的日志形如 `渲染器 101，可见 89，含并列的组 4，实测对 12`：**`可见` 必须是正数**，
出现 `可见渲染器 **0** 个` 就是目标选错了。

**这批角色还要"强制打开渲染器"**：它们在场景里是 **Renderer 级 disabled**
（`activeInHierarchy=true` 但 `enabled=false`，游戏运行时按需开），只 `SetActive(true)`
画不出来 ⇒ `ForceEnableRenderers=true`（默认）会在采样每帧临时 `enabled=true`、
记原值、帧末还原。日志里应有 `…：临时打开 N/M 个原本 disabled 的渲染器（采完还原）`。
另外产物目录名用"从场景根到目标的完整路径"（避免多个角色的 `size_root` 同名互相覆盖）。

**隔离方式（2026-09-17 晚改的）**：不再"全部激活再一起导"，而是**逐个目标**：
把其它角色**整根 `SetActive(false)`**（脚本/Animator 也停）+ 关掉它们所有渲染器 →
只激活当前这一个（含父链）→ 采完**立刻把它关回 inactive**、其它角色还原。
所以任一时刻场景里只有 1 个角色是活的，JSON 里记 `targetIndex/targetCount/isolated`。

跑法：菜单 `Tools/2DModel/运行时采样/渲染顺序导出：按内置清单开始`（自动进 Play，
采完退出；日志 `D:\VB\Unity2Spine\info\_logs\play_sample.log`）。

产物：`info\_draworder_<角色>\<角色>__<状态>__t<毫秒>.json`（每个渲染器一条 +
并列组 + 成对实测结果 + `drawOrderFirstToLast`）与 `frames\*.png`（白底 + `_cam.txt`）。

### 8.3 环境/策略坑

1. PowerShell 删文件常被策略拦：删就单独一条命令、用绝对路径、先校验前缀；
   整理文件优先**只挪不删**。
2. 管道给 Python 传中文要先 `$env:PYTHONIOENCODING="utf-8"`，否则中文正则/文件名变 `?`。
3. 长任务别 `sleep` 干等：用 `Start-Process -Wait` 或在会话里轮询输出；
   量内存用 `tools\mem_probe.ps1`。
4. 写 `.ps1` 一律**只用 ASCII 注释**（PS 5.1 按 ANSI 读，中文注释会把文件读坏）。
