## 1. 结论：**能，而且能小一个数量级**

`cerberus_skin1` 的同一条 `lobby` 动画：

| 表示 | JSON 大小 |
| --- | --- |
| 现状：单根骨 + 逐帧逐顶点 deform | **5.45 MB** |
| 分骨骼，不抽稀（174 骨 × 233 帧，translate/rotate/scale 全写） | 4.82 MB |
| 分骨骼，骨键抽稀 0.5 单位 | **0.48 MB** |
| 分骨骼，抽稀 2 单位 | 0.31 MB |
| 分骨骼，抽稀 5 单位 | **0.24 MB** |

⇒ 同样一条动画，**抽稀后是现状的 1/11 ~ 1/23**。原因是：

* 现状的 deform 是"**顶点 × 帧**"（每帧每个顶点都要写偏移），和动作复杂度无关；
* 分骨骼是"**骨 × 关键帧**"，而且 Spine 会**插值**，所以能按阈值抽稀。

粗估整个 `_probe50_rt4`（现 3.89 GB，其中 JSON 3.14 GB）：分骨骼后 JSON 大概落到
**0.2~0.6 GB**，整目录 **~1 GB 上下**（`.skel` 也可以不用了，因为 JSON 变小、
加载不再是瓶颈）。

## 2. 原型怎么做的（与 Unity 的骨骼设定对齐）

* **骨**：每个"被部件用到过的 Unity transform + 其祖先"→ 一根 Spine 骨；
  局部 TRS 直接从采样器拿（Unity 的 `T·R·S` 与 Spine 的骨模型一致），
  拆成 `x/y/rotation/scaleX/scaleY`（镜像表现为 `scaleY<0`）。
* **SkinnedMeshRenderer 部件** → **加权 mesh**：
  * 顶点 = setup 姿态下的**世界坐标**（复用主转换器的 `_part_points`）；
  * 权重 = Unity mesh 的 `m_VertexData`：**`weights[vi][k]` 要配 `boneIndexRaw[vi][k]`**
    （后者是 `m_Bones` 的下标）。实测 `parts_breastbelt_03`：
    `weights=(0.75,0.25,0,0)` + `boneIndexRaw=(1,0,0,0)` ⇒ **0.75×m_Bones[1] + 0.25×m_Bones[0]**。
    ⚠️ 一开始按"第 k 个权重配第 k 根骨"写，**错了**（多骨部件会整体跑偏）。
  * `bones` 只列**实际用到的**骨，每顶点权重个数**必须等于** `bones` 长度。
* **SpriteRenderer / static 部件** → 挂在"自己的 transform 骨"上的**无权 mesh**
  （顶点在骨局部）。
* **动画** → 每根骨的 `translate/rotate/scale` 关键帧（可抽稀）。
* **贴图集**直接复用现有产物（`path: tex0/tex1` + 同样 uvs）。

## 3. 路上修掉的两个真问题（都对体积/正确性有影响）

1. **悬空父骨**：Unity 根 transform 的 `m_Father` 是 `0/None`，我一度把它当成
   "编号 0 的骨"，于是写出了 `"parent": "node_0"` 这种不存在的父 ⇒ **spine-cpp 一加载就
   `0xC0000005`**。修法：`need.discard(0/None)` + 只在 `fa and fa in need` 时写 `parent`。
   （骨**必须先父后子**：Spine 解析时按名字找父。）
2. **权重与骨下标的配对**（见上，用户提示"参考 Unity 的骨骼设定"后定位）。

## 4. 还没闭环：加权 mesh 仍会让 spine-cpp 崩

现状：**无权 mesh 全部正常**；加权 mesh **部分正常**（`parts_breastbelt_03`，3 骨 18 顶点
OK），但另一些（`parts_L_leg_04`，2 骨 48 顶点）**一加载就崩**。已排除：

| 试验 | 结果 |
| --- | --- |
| 该附件原样 | CRASH |
| 加 `hull` | CRASH |
| 把槽位骨换成非零缩放的骨 / 修掉那条 `scaleY=0` 的骨 | CRASH |
| 只留 1 根骨 + 权重 1.0 | CRASH |
| 换成能跑部件的骨名 | CRASH |
| **最小 4 顶点 1 骨加权 quad**（两个槽位都试） | **CRASH** |
| 同槽位换成**无权** mesh | OK |
| `parts_breastbelt_03` 的**完整**加权附件 | OK |

⇒ 不是"零缩放骨"、不是 uvs/tris、也不是骨名，而是**我写的加权 mesh 格式还有一处
和 spine-cpp 3.8 的要求不一致**（最小 quad 都崩，说明是格式/必需字段级别的问题，
不是数据个例）。下一步要么继续二分 spiene-cpp 的 `SkeletonJson::readMesh`
（`hull`/`vertices`/`weights` 的必需组合），要么**先走无权路线**：

* 大多数部件在 Unity 里本来就是"单骨刚性"（现有转换器的 sprite/静态件、以及
  `weights` 通道为空只有 `boneIndexRaw` 的件）⇒ 直接挂到骨上，**不需要权重**；
* 只有"多骨真蒙皮"的件（腿、裙、布）才需要加权 —— 可以先按"主骨"刚性挂，
  视觉上通常够用，等加权格式吃透了再换真权重。
