# 综述：Unity 2DModel → Spine 3.8 离线转换

更新：2026-09-18。这份是**总览**（一页把项目说清）；动手细节看
[`总正确转化.md`](总正确转化.md)，上手看 [`交接必看.md`](交接必看.md)，
**接手/核查看 [`交接与核查.md`](交接与核查.md)**（问题清单 + 可用技术手段 + 标准流程）。

---

## 1. 一句话

把 Unity 工程里的 **2D 立绘 prefab**（`SpriteRenderer` + `SkinnedMeshRenderer` +
`Animator`，原生 Unity 2D 或老 NGUI 两条路线）**离线**转成 **Spine 3.8**
（JSON / atlas / `.skel`），并给出可复现的校验闭环；**只用磁盘静态资源**，
Unity 编辑器导出的 PoseFrames / PlayFrames **只做校准，不进成品**。

## 2. 产物契约（一个角色一个目录）

| 文件 | 内容 |
| --- | --- |
| `<角色>_static.json` | 1 根 `Root` 骨 + 每部件一个 slot/mesh + `deform` 时间线（逐帧形变已把蒙皮烘进去） |
| `<角色>_static.skel` | 同一份数据的二进制（查看器优先读它：**快 7.1 倍、内存 1/15**） |
| `<角色>_static.atlas` + `_N.png` | 图集（按用到的贴图打包，加色件单独一页） |
| `_static_info.json` | 对账手册：prefab/scene/clip/dt/units/origin/flipX/partsMeta/relativeLayers… |
| `.config.json` / `README.md` | 查看器配置 / 可读摘要 |

单位默认是**源图像素**（`units:"px"`，1 单位 = 1 像素 = 1/675 世界单位），
`origin` 记 Unity 世界的贴图原点；加色部件按 alpha 预乘。

## 3. 架构（2026-09-17 库化后）

```
src/unity2spine/
  unity/    prefab/scene 解析、Transform/TRS、SkinnedMeshRenderer、AnimationClip 曲线求值
  ngui/     老 NGUI 路线（UIAtlas 打包、PrefabModel、逐帧合成）
  convert/  2DModel 转换：static_prefab_spine（主）、convert_2dmodel（共用几何/历史）、
            frame_baked / single_frame_spine
  spine/    Spine 3.8 输出：spine_out（JSON/atlas）、spine38_binary_writer（.skel）、
            sprite_outline（没网格时按 alpha 复刻轮廓）
  validate/ validate_spine（自检）、merge_existing_spine（把已转好的 Spine 合并）
```

配套：

| 目录 | 作用 |
| --- | --- |
| `gui/` | Tkinter 界面（两条路线 + 校准/检查 + **交付/维护**：批量、补 `.skel`、显隐校验、内存护栏） |
| `tools/` | 命令行：批量转换、写 `.skel`、静态检查、几何/单脸校准、显隐校验、渲染、内存探针 |
| `bones/` | **分骨骼瘦身试验（已搁置）**：结论是能小 1/11~1/23 |
| `docs/` | 本套文档（综述 + 4 份常读 + 专题） |
| **`info/`** | **Unity 侧动态导出的统一根（2026-09-18 起，18.7 GB）**：`_refshot_*` / `_draworder_*` / `_inspect_*` / `Data\{PoseFrames,PlayFrames,Frames,SceneT0,…}` / `_logs\`；**怎么导见 [`导出指南_Unity运行时数据.md`](导出指南_Unity运行时数据.md)** |
| `_probe50_rt4/` | 当前产物（50 个角色，含 `.skel`） |

`ngui2spine/`（仓库根）与 `src/unity2spine_compat/` 是**老 import 名的兼容层**：
`python -m ngui2spine.static_prefab_spine …` 照旧能跑。也支持
`pip install -e .`（`package-dir = src`，控制台命令 `unity2spine-convert`）。

## 4. 数据流（五步）

```
prefab/场景 ─解析─> 层级 + TRS + Renderer/材质 + clip 曲线
   ├─ 选主 clip（lobby 之类待机）；setup 姿态 = 该 clip 的 t=0
   ├─ 逐帧：clip 曲线求骨骼局部 T/R/S → 世界矩阵 → 蒙皮/静态顶点
   │        （结果写成该部件的 deform 关键帧；**几何完全来自磁盘数据**）
   ├─ 绘制顺序：`(sortingOrder 取整, 同值内 −层级DFS序)`
   └─ 显隐/颜色/形变/换贴图 → slot 附件 / color / deform 时间线
```

## 5. 关键规则（都被真值或实测验证过，细节见 `总正确转化.md`）

1. 世界矩阵 `M = T·R·S`（按列缩放）——写成 `T·S·R` 会让非均匀缩放件朝向全错。
2. 蒙皮 blend 索引两种编码（整数 / float 位模式）都要认。
3. 曲线 `path` 折行要拼回去（超长路径 Unity 会续行）。
4. `path_0x…` **哈希路径**要还原（= CRC32(相对宿主路径)），否则整条曲线丢。
5. Sprite 的网格**直接读精灵资产**（`m_RD`），alpha 轮廓只兜底 → 头脸"碎块"消失。
6. 多材质网格按 **submesh** 拆 → 挎包"棕色小块"消失。
7. 没有 `m_Enabled` 曲线时回落渲染器**静态** `enabled` → 骨骼 gizmo 圆环不再出现。
8. 显隐按**运行时口径**：插值 + `|v|>1e-3`（不是 `v≥0.5`）。
9. 颜色时间轴**共线才丢帧**。
10. 一个 controller 挂两个 Animator 时按 `(controller,state)` 去重（babariana 22→11 条）。
11. 副 Animator 的 path 相对**它自己**的宿主；副层的默认 clip 要合并。
12. **绘制顺序 = `(sortingOrder, 同值内 −DFS序)`**（2026-09-17 用 Unity 的
    `Renderer.sortingKey` 实测：5,012 条非并列关系 100% 解释）。
13. 同 order 内"相对层级会变"才需要多 drawable；默认关（会把形变写 N 遍）。
14. 大产物必须同时写 `.skel`。
15. `.atlas` 末尾要有一个换行（否则多页 atlas 会让 spine-cpp 越界读崩）。
16. **`m_Bones` 非空但全是空引用的 `SkinnedMeshRenderer`，Unity 一个像素都不画**
    （蒙皮矩阵为空 ⇒ 顶点塌成一点；渲染器自己仍 `isVisible`、`bounds` 照报，
    所以导出脚本和四层校验都看不出）——必须排除，否则会多出"飘在身外的头发 /
    叠在眼睛上的表情层"（2026-09-18 定案，见 `历史问题与修复.md` 第 8 节）。
    ⚠️ 注意 `m_Bones: []`（**空列表**）**不在**此列：Unity 照常渲染
    （arman 的眼镜/红晕就是空列表且正常显示）。
17. **同名孪生节点，曲线只绑"第一个"**：Unity 的绑定键是**路径 + 同名序号**，
    同一路径下的第二个节点**保持 prefab 姿态**；我们按路径字符串一对多绑定，
    会把同一套曲线套给所有同名节点 ⇒ 多画一件（banshee 手腕"多一块 + 硬黑线"、
    `brownie_skin1` 左手）。修法：节点表加"同名序号"，曲线只绑 `#1`（**待修**）。
18. **`m_SortingOrder` 是可动画属性**：Unity 逐帧按它排序（引擎
    `SetBoundCurveFloatValue` case 10 = SortingOrder）；我们把顺序烘成静态 slot
    顺序、`multiDrawable` 默认关 ⇒ 该压在上面的件被盖住（draculina"抓绳子"的手
    看不见）。修法：把逐帧排序写成 Spine 3.8 的 **`drawOrder` 时间轴**（**待修**）。

## 6. 校验闭环（四层，按顺序做）

| 层 | 工具 | 判据 |
| --- | --- | --- |
| ① 结构 | `tools\static_check.py` | 四项全 0（引用了却没导出 / 静态可见没导出 / 与真值冲突 / 曲线 path 对不上） |
| ② 几何 | `tools\calib_geo.py` | 逐顶点世界误差（三主力 ≤0.002） |
| ③ 显隐 | `tools\check_clip_visibility.py`（对 clip）/ `check_play_visibility.py`（对 Play 真值） | 逐槽位时间轴一致 |
| ④ 观感 | `tools\rt_frames.py` + 同帧真值 + `_scratch\cmp_truth.py` | 同帧差异只剩边缘抗锯齿 |

> "谁盖谁"这类问题前三层看不出来，必须第 ④ 层同帧对照；排序规则本身则是用
> **Unity 侧成对隔离渲染实测 + 反汇编**定的（见
> [`渲染顺序_反汇编研究.md`](渲染顺序_反汇编研究.md)）。

第 ④ 层现在有个顺手的入口：**`_scratch\truth_diag.py`** —— 把我们的渲染按相机
参数贴到 `info\_draworder_*` 的参考帧上，**逐渲染器**报差分，还能列出
"差>48 的连通块"落在哪个件上（2026-09-18 用它一次定位了"飘头发/表情重叠"）。
配套：`_scratch\variant_probe.py`（做产物变体，验某一件到底有没有用）、
`_scratch\cmp_product.py`（两份产物**按 path** 对账）。

### 6.1 两条硬手段（判断不了时先想到这两条）

| 手段 | 是什么 | 入口 |
| --- | --- | --- |
| **C# 脚本导 Unity 运行时数据** | Play 模式下把 Unity 的**真值**导出来：参考帧（PNG+相机+逐渲染器显隐/排序/世界顶点）与**渲染顺序**（排序键 + 成对隔离实测"谁盖谁"，还能**反射读内部属性 `Renderer.sortingKey`**） | `Assets\Editor\PlayRefShot.cs`、`Assets\Editor\ExportDrawOrder.cs`，菜单 `Tools/2DModel/运行时采样/…`；日志 `D:\VB\Unity2Spine\info\_logs\play_sample.log`；读结果 `python tools\read_draworder.py <目录>` |
| **反汇编（IDA）做源码校对** | Unity 没源码，但引擎算法能从 DLL 读出来：拿"引擎真实行为"给我们的实现对表 | `_reverse\UP2022.dll.i64` + `tools\ida_q.py`（`names/strings/disasm/decompile/...`）；地址清单见 [`渲染顺序_反汇编研究.md`](渲染顺序_反汇编研究.md) |

以及 `weights[k]` 必须配 `boneIndexRaw[k]` 这类骨骼语义。

## 8. 怎么跑

```powershell
# GUI（推荐先看这个）
python gui\gui.py            # 或双击 gui\run_gui.bat

# 单个角色（新旧两种写法都行）
python -m ngui2spine.static_prefab_spine <prefab> <out> `  # 兼容层
  --assets <Assets> --scene <save.unity> --skel --no-face-check
python -m unity2spine.convert.static_prefab_spine <prefab> <out> ...   # 新库

# 批量 + 补 .skel（重活：先量内存）
python tools\convert_all_2dmodel.py --prefab-dir <目录> --out <产物> --jobs 2 --scene <save.unity>
python tools\write_all_skel.py <产物> --force
```

**内存红线**（踩过）：大产物只走 `.skel`（`draculina` 的 JSON 一加载就 10.5 GB）；
连续加载骨架的脚本会线性泄漏，要 `--max 5` 分片；重活前用
`tools\mem_probe.ps1` 量进程树峰值，同时跑的峰值之和 ≤ 10 GB。
