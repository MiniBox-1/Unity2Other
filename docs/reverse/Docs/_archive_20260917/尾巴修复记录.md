# alice 尾巴修复记录（现象 / 根因 / 各版做法 / 量化验证）

对象：`Assets/prefabs/test/alice_skin1_origin/2DModel_3P_Alice_NS1.prefab` 与
`Assets/prefabs/test/alice_skin1_dl_origin/assetbundleresource/character_2d/2DModel_3P_Alice_NS1_DL_N.prefab`
（`parts_Tail_end` = 尾巴尖精灵，`parts_Tail_F` / `parts_Tail_B` = 尾巴条的两段）。
相关已知问题另见 `已知问题.md`（被禁用的 Renderer 仍被导出）。

## 1. 现象

1. 播放动画时 **尾巴尖与尾巴条脱开**，条末端被拉成一条**细刺**（idle/start 轻、tep/breast 重）；
2. 条末端那根**细长的线**（静止时也在，位置固定）；
3. 修好后一度出现**一抽一抽的抖动**（速度在每个 0.05s 关键帧处掉到 0）；
4. breast 里条出现**明显折角**而不是圆滑曲线。

## 2. 根因

### 2.1 两套骨骼 + 缺失的运行时脚本

尾巴是两条链：

```
可见 spline 控制链（被动画驱动）
  Bone_Tail_0 → Bone_Tail_01 → CTRL_Spline_Tail → spline_GRP_1
    → spline_Ctrl_GRP_1..7/spline_Ctrl_1..7
    → spline_Ctrl_7/Bone_Tail_End →（子物体）parts_Tail_end 尾巴尖

变形骨链（网格权重用的就是它，整段静止）
  Global_CTRL/Controllers/CTRL_Spline/bone_1 → … → bone_31
    → Bone_Tail_02 … Bone_Tail_32
```

`parts_Tail_F` 权重 = `Bone_Tail_19..32 + Bone_Tail_End`；`parts_Tail_B` 权重 =
`Bone_Tail_0..21`。原工程里应由一个**运行时脚本**把 spline 控制点解算到变形骨上，
ripoff 出来的 prefab 里该脚本已丢失（`Assets/prefabs/lo/**` 1940 个 prefab 里
MonoBehaviour 只剩 spine 的 3 个类）⇒ 动画一播：尖跟着 spline 飞走、条不动，
末端 8 个顶点（权重 0.88 在 `Bone_Tail_End`）被拉成细刺。

量化：idle/start 里变形骨链位移 **0.0000**、`spline_Ctrl_*` 位移 0.014~0.13；
breast/tep 里 `spline_Ctrl_7` 最大 83°/0.19 世界单位，`Bone_Tail_End` 最大 26.5°。

### 2.2 bind 姿态 ≠ prefab 静止姿态（细线与细刺的真正来源）

网格的 `m_BindPose` 与 prefab 里的静止姿态并不一致：

* 末端：`bind[32]·bind[End]⁻¹ = 平移(-0.4066,0,0)`（无旋转、单位缩放）——即
  绑定时 `Bone_Tail_End` 在骨链末端，而 prefab 里它偏了 ~0.18 世界单位；
* 中段：`parts_Tail_B` 里有几对**网格坐标相差 ~2e-5、权重却不同**的顶点
  （v72/v73：0.45/0.32/0.23 vs 0.51/0.29/0.21），骨一有相对运动就被拉开
  **0.026~0.0275 世界单位**（≈19 源像素）——就是那条"细长的线"。

> 完全重合的顶点对只有 2 对（`parts_Tail_B` v0↔v48、v2↔v46），两边权重相同，
> 不参与这条线。

### 2.3 骨密度（折角的来源）

条是 42~61 列的缎带，只由 31 根骨（间距约 0.057 世界单位）驱动，弯曲时天然
"每骨一段 + 权重过渡"；原动画里条**根本不形变**，所以看着是圆的。

## 3. 各版做法与结果（都留了产物/备份，可回看）

| # | 做法 | 结果 | 产物 |
| --- | --- | --- | --- |
| 1 | **改 prefab**：`Bone_Tail_End` 从 `spline_Ctrl_7` 移到 `Bone_Tail_32` 下，局部变换 = `bind[32]·bind[End]⁻¹` | 尖与条合成漂亮"箭镞"，但**尖被挪走 ~0.27 单位**，尖下面的阴影留在原地 → 用户否掉 | `_scratch\spine_dl_fixed\`、`cmp_tail_tep655.png` |

| 3c | **切线改中心差分** + 局部四元数符号连续 | 速度连续：`0.099 0.098 0.098 0.099 0.100 0.101 …`，最大加速度 74.5→**5.0~7.0**，关键帧边界/帧间加速度比 **1.02~1.05** | `clip_backup3\` 起 |
| 4 | **IK（FABRIK）**：两端钉住（基座跟 guide、末端 = 尖的绑定姿态），骨长严格不变 | 拉伸消失（条最长边 0.068→0.061，静止基准 0.056），但急弯处内缘压缩出折痕（细三角最坏比 71/154） | `_scratch\spine_dl_v4\` |

| 6 | 参考姿态改用**网格 bind**（`参考[i]=W_End·bind_End·bind_i⁻¹`） | 细线确实消失，但 F/B 是两个网格、bind 空间不同，B 被挪到别处（混用锚点）→ **未采用** | `_scratch\spine_dl_v7/v8\` |

当前仓库/工程状态：**第 5 版**（F 动、B 静止、无 IK、切线已修），尾巴尖与阴影不动；
`.anim` 里只有 `Bone_Tail_19..32` 的位置/旋转曲线。

## 4. 工具与用法

### 4.1 烘曲线：`tools/unity_validation/BakeTailSpline.cs`

（工程内已装一份：`Assets/Editor/BakeTailSpline.cs`）

* 菜单：`Tools/2DModel/尾巴/把 spline 解算烘进各 clip`（默认 ik=0、fonly=1）
* 批处理：

```bat
set TAIL_BAKE_JOBS=D:\VB\Unity2Spine\_scratch\tail_bake_jobs.txt
set TAIL_BAKE_REPORT=D:\VB\Unity2Spine\info\_logs\tail_bake.txt
Unity.exe -batchmode -projectPath D:\VB\Search\NormalLocal\lastOrign -quit ^
  -executeMethod BakeTailSpline.BakeJobsFromFile -logFile D:\VB\Unity2Spine\info\_logs\tail_bake.log
```

任务文件每行：`<prefab 资源路径>|<clip;clip;…（留空=用 controller 的 clip）>|ik=0/1|fonly=0/1`

* `ik=1`：额外做 FABRIK（骨长不变）；`fonly=1`：只烘 `parts_Tail_F` 用到的骨。
* 幂等；每个 clip 烘 31 根骨 ×（时长/0.05+1）帧；写出 `localPosition.*` / `localRotation.*`
  曲线，切线用中心差分（**不要用默认 0 切线**）。Unity 会把绑定表写成

> 2026-09-13：切线模式改用新 API —— 旧写法 `keyframe.tangentMode = 1` 已废弃
> （CS0618），现在写成 `AnimationUtility.SetKeyLeftTangentMode/SetKeyRightTangentMode(
> curve, i, AnimationUtility.TangentMode.Free)`，语义不变（Free = 尊重我们写进去的
> 中心差分切线；若改成 `Auto`，Unity 会自己重算切线，中心差分就白算了）。
> 注意必须在 `MoveKey` **之后**再设模式，否则会被重置。
  `genericBindings: []`（它自己会重建，不必手写 crc32）。

## 5. 验证口径（每次改完都跑）

1. `tools\static_check.py` / 导出末尾的静态检查：四项计数全 0
   （当前 DL：场景渲染器 139 / 导出部件 129）；
2. `tail_verify.py`：条最长边 ≤ 0.07、尖→条间距不随动画漂移；
3. `jitter_check.py`：关键帧边界/帧间加速度比 ≈ 1（不允许 0.1~0.2 那种"一格一格"）；
4. `tools\spine_raster.py` 出图（`--only slot:parts_Tail_*` 可单独看 B/F/尖），
   必要时 `node D:\VB\vision.js <图> "<问题>"` 复核；
5. 与 Unity 真值（`info/Data/PoseFrames`）比对时注意：**尖的偏差应为 0**
   （我们不动它），条的偏差是"修"（旧真值本身就是条不动、被拉刺的坏状态）。

## 7. 一句话总结

**尖不动**（连它下面的阴影）：把解算烘进 clip，锚点用 `spline_Ctrl_1..6` +
`Bone_Tail_End`，末端因此与尖共享同一刚体运动；曲线切线必须给（否则一抽一抽）。
剩下的细线与折角是**网格/绑定**层面的问题（bind ≠ 静止姿态、骨密度不足），
改曲线解决不了，需要动 `parts_Tail_F/B.asset`。
