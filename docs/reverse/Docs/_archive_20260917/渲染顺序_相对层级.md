## 1. 需求（用户原话）

> 把**所有 RenderOrder 的渲染改为计算相对层级**。如果一个组件的相对层级老是变化，
> 则**分配多个 drawable**，启用哪个层级用哪个。
>
> —— `_probe50_rt2/Question/qustion.txt`（同时给了 15 张问题截图，见第 8 节）

即：**顺序不能再由动画时间轴去"切换"，而要由静态的槽位安排决定**；随机位变化的部件
就多开几个槽位，动画只负责"亮哪一个"。

## 2. 旧方案（drawOrder 时间轴）为什么必须换

Unity 的透明渲染顺序 = `(sortingLayer, m_SortingOrder, 到相机的距离)`；本项目只用到
`m_SortingOrder`（int，曲线求值后按 `SetBoundCurveFloatValue` case 10 取整，
见 `unity_int_round`）。等价表述是：**把这种成对顺序写进槽位表**。

旧方案把它编成 Spine 3.8 的 `drawOrder` 时间轴，有两条硬伤：

1. **表达力不够**：Spine 的 drawOrder 只能把槽位**往前挪**（binary 里 offset 是
   unsigned varint）。整体重排（A 从第 3 位跳到第 40 位）无法表达，
   旧实现只能"整条动画不导出 drawOrder"，于是 draculina 的手部层级永远是错的
   （见 `已知问题.md`）。
2. **会被运行时数值放大**：drawOrder 是按**全局顺序**写的，而画面上只有
   **互相重叠**的部件之间"谁在前"才有意义。用全局 rank 统计时：

   | 角色 | 部件 | 全局 rank 会变的部件 | 需要槽位 | 最多层 |
   | --- | --- | --- | --- | --- |
   | banshee_skin1 | 78 | 0 | 78 | — |
   | cerberus_skin3 | 101 | 16 | 117 | 2 |
   | **draculina_skin1** | 100 | **100** | **3130** | 74 |
   | andvari_skin2 | 63 | 0 | 63 | — |

   draculina 的 100/100 其实是"**一个**部件跨过很多**不和它重叠**的部件"造成的
   ——那些位置变化观众根本看不到。

**结论：层级要按"重叠邻居内的相对次序"算，不能按全局 rank。**

## 3. 算法（`relative_layers()`）

```
1) 空间重叠关系
   对每条动画的若干采样时刻，求每个部件的世界 AABB；取并集并外扩 20%，
   相交 = "邻居"。邻居关系**与时间无关**（保守：任一时刻重叠过就算邻居）。

2) 逐时刻的相对层级
   t 时刻先按 (sortingOrder 取整值, 静态下标) 排出绘制顺序 order；
   部件 i 的相对层级 = 它**重叠邻居**里排在它前面的个数。

3) 一个部件在整条动画里取到多少个不同层级 ⇒ 就给它几个 drawable。

4) 槽位顺序 = 按 (相对层级, 静态下标) 排。
```

### 正确性

任意时刻 t，若 i、j **重叠**且 i 画在 j 前，则 j 的层级计数里必然含 i，
而 i 的计数里不含 j，故 `depth_i < depth_j` —— **重叠对的层级严格不等**，
按 `(层级, 下标)` 排出的槽位序在所有时刻都与运行时一致。
不重叠的对随便排，画面上看不出来。

### 采样时刻必须包含"排序值的跳变点"

`m_SortingOrder` 是插值曲线 + int 属性，"值变整数"发生在**斜坡中段**、不在关键帧上。
因此 `probe_times(e)` 现在额外并入：

```python
for keys in (cl.get("sorting") or {}).values():
    for kt, _v in keys: ts.add(round(kt, 6))          # 关键帧
    ts.update(sorting_change_times(keys, None))        # 取整后值变化的时刻（二分求）
```

否则换层时刻会被采样步长整个跳过（表现为"层级晚一拍"）。

## 5. 踩到的真 bug（值得记一笔）

第一版 `relative_layers()` 把**部件字典** `{"part": Part, …}` 直接传给了
`order_at()`，而 `order_at()` 是按 `part.sorting_order` 属性排序的 ——
`getattr(dict, "sorting_order", 0)` 恒为 **0**，于是"排序值全相等 ⇒ 顺序恒定 ⇒
相对层级永远不变"，16 个角色全报 **0 变层**（假阴性）。

修法：在 `relative_layers()` 里统一取一层
`pl = [e["part"] if isinstance(e, dict) else e for e in kept]`。
修完 cerberus_skin3 立刻从 0 变成 6 个部件要 2 层。

> 教训：**"0 变层" 不能当结论**，要先看"重叠邻居数"是不是非零
> （`tools/layer_report.py` 会一起打印）。
