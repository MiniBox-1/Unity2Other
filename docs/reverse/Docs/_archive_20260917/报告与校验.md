### 2.3 这一轮修掉的根因（细节见 `静态prefab路线.md` 第 3 节）

| # | 问题 | 影响面 |
| --- | --- | --- |
| 1 | clip 按**资源名**而不是 state 名选择 | 9 个角色 |
| 2 | px/unit 估算放宽（细长件多的角色曾掉到兜底 100） | carolina 等 |
| 3 | rest 表按宿主**全路径**截断（同名节点互相覆盖） | carolina（曾被放大 7 倍） |

| 5 | 比对工具过滤真值异常（BakeMesh 吐 1e20+ 坐标） | banshee 等 |
| 6 | **移除权重通道的“兜底猜测”**（把 tangent 当权重） | baekto 等，IoU 0.409→0.998 |

## 三、Clip 曲线属性扫描

工具：`tools/check_clip_attributes.py`

```bat
python tools\check_clip_attributes.py D:\VB\Search\NormalLocal ^
  --json docs\data\clip_attributes_report.json        :: 全项目扫描
python tools\check_clip_attributes.py <Assets> --only-prefab <prefab>   :: 单角色
```

输出四档：**已处理** / **未处理·有实际动画（要处理）** / 未处理·全程恒定值 /
已评估·不导出；有“未处理·有动画”时退出码为 1。

`.anim` 里的 `attribute` 既可能是属性名，也可能是属性名的 **CRC32**
（`typetree_2526845255`），脚本会反查成 `m_Color.r` 之类。

| 转换器已处理 | 用途 |
| --- | --- |
| `m_LocalPosition/Scale/Rotation`、`localEulerAnglesRaw` | 采样成 mesh deform |
| `localEulerAngles`（写在 `m_FloatCurves` 里的旧写法） | 同上，按欧拉角解析 |
| `m_IsActive` / `m_Enabled` | slot attachment 时间轴（表情备选件、眨眼） |

| 已评估、明确不导出 | 原因 |
| --- | --- |
| `m_Color.*`（含 typetree 写法） | 实测 Unity 里未生效：aeda 发光星这三条曲线恒为 0，套用后光晕层 IoU 0.935 → 0.837 |
| `m_FlipX/m_FlipY`、`m_Size.x/y` | 静态值已体现在 setup 顶点里 |
| `m_Sprite` | 换图曲线，静态 prefab 路线不支持 |
| `m_SortingOrder` | 静态路线按 setup 排序，不跟随动画 |

三主力结论：audrey、blacklilith “未处理·有实际动画”均为 **0**；
aeda 只有 1 条 `ParticleSystem_*`（粒子对象，不属于 2DModel 部件）。

全项目 1878 个 `.anim` 扫描：未处理但有动画的属性 748 种，其中
`blendShape.*` 721 种（10021 次，本路线用骨骼变形，不处理）、
`material.*` 13 种、`script.*` 13 种、`ParticleSystem_*` 1 种，
都不在三个主力角色的 prefab 里。换角色导出前先用 `--only-prefab` 扫一遍。

### 4.2 历史：帧烘焙路线（已被静态路线取代）

早期三条路线都不达标：纯离线解析骨骼（散件错位）、Unity 真值锚定（缺静态底图层）、
仿射/UV 配准（vision 复核发现肢体扭曲）。随后改用**帧烘焙**：读
`info/Data/PoseFrames/aeda_normal.json` 的逐帧真值直接写 mesh + deform
（`ngui2spine/frame_baked.py`），产物 `samples/2DModel/aeda/anim_v2`
（323 帧 / 16.1s / 43 部件），当时通过 vision 认证。它的问题：**依赖 Unity
运行态导出**，不符合“只用磁盘静态资源”，因此被静态路线取代。

帧烘焙阶段积累、并对静态路线同样有效的修复：Sprite 四角公式
`l = -pivot*rectSize/ppu`；sprite rect 缺失时回落离线元数据；UV 的 v 方向；
头部脸片的 slot 插入位置；cam.txt 带 BOM 时按 `utf-8-sig` 读。
