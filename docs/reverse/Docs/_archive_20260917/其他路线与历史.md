## 1. Unity 动画与 NGUI 介绍（BdOne 项目）

BdOne 动态立绘使用的不是 Animator/AnimatorController，而是旧版 `Animation`
组件 + `AnimationClip(.anim)`：

- `.anim` 是文本 YAML，一个 clip 里按 `path` 保存多条曲线；
- 主要曲线类型：
  - `m_RotationCurves`：局部旋转（四元数，约 10fps 关键帧）；
  - `m_PositionCurves`：局部位移（少量关键帧 + 三次 Hermite）；
  - `m_FloatCurves`：`m_IsActive`（显隐/眨眼）、`mColor.*`（透明度等）；
  - `m_ScaleCurves`：本批资源基本为空。
- 无加权模式时 Unity 用三次 Hermite 插值；极值斜率 `Infinity` 表示"整段保持
  左键值，到右键瞬间跳变"。

立绘由 NGUI `UISprite` 拼装：一个"服装子装配" = 根 GameObject + 若干
`UISprite` 子节点；UIAtlas(`.asset`+`.png`) 记录每个 sprite 的裁切矩形与
padding。NGUI 运行时把裁切块按整帧画布比例放大后放回 widget：

```text
px = widgetWidth  / (paddingL + width + paddingR)
py = widgetHeight / (paddingB + height + paddingT)
部件位置 = 根据 padding 放回 widget 内
部件尺寸 = width*px, height*py
```

绘制顺序按 `mDepth`；`mColor.a` 与 `m_IsActive` 常被动画曲线驱动。

示例 `Assets/prefab/chr/安洁利卡.prefab`：根下有"艾莉希斯/原皮/素净的比基尼/
圣诞"等服装子装配，每个子装配自带 Animation + UIAtlas。

## 2. Spine 3.8 要点（输出侧）

```text
xxx.json      骨骼、插槽、皮肤、动画
xxx.skel      同一份骨架的二进制容器（可选；见 静态prefab路线.md 9.3）
xxx.atlas     图集文本
xxx.png       图集图片
```

1. **骨骼 setup pose**：每根骨骼保存局部 `x, y, rotation(度), scaleX,
   scaleY, shearX, shearY`；父子用数组顺序（父在前）+ `parent` 名字；
   世界变换为 2D 2x3 矩阵，y 向上、旋转逆时针为正。
2. **动画关键帧是相对 setup 的值**：`rotate/translate/shear` 为加法，
   `scale` 为乘法。
3. **曲线**：无 `curve` = 线性；`"stepped"` = 台阶；贝塞尔用扁平字段
   `curve/c2/c3/c4`，挂在区间左侧关键帧上。
4. **时间**：单位秒；clip 时长 = 各时间线最后关键帧的最大值；循环由运行时
   外部 wrap。
5. **图集**：本项目离线渲染器与官方 3.8 样例读 `.atlas` 的 `xy` 时以图片
   **左上角**为原点；`format` 必须写 `RGBA8888`；页头后与 region 之间不留空行
   （空行只用于分隔多页）。

> 关于预乘 alpha（PMA）与加色混合的依赖关系，见
> `静态prefab路线.md` 第 6 节。

## 3. NGUI → Spine 转换原理

```text
Unity prefab(.prefab) + .anim + UIAtlas(.asset/.png)
        │
        ├─ 1. 解析 Unity 文本 YAML（unity_parse.py）
        ├─ 2. 建树：Transform/UISprite/Animation -> 服装子树（ngui_model.py）
        ├─ 3. 解析 .anim 曲线并采样（ngui_anim.py / anim_to_spine.py）
        ├─ 4. 生成 Spine 骨架 JSON（spine_out.py）
        ├─ 5. 收集用到的图集裁切块，重打包尽量一张图（pack_images.py）
        └─ 6. 结构校验（validate_spine.py）
```

映射规则：

- 一个服装子装配 = 一个 Spine 骨架；Unity 端仍像原来一样多套叠放；
- GameObject → Bone：`localPosition.x/y` → `bone.x/y`，四元数 → 局部 z 角，
  `localScale` → `bone.scaleX/scaleY`；y 向上与 Spine 一致，无需翻转；
- UISprite → Slot + RegionAttachment：用 NGUI padding 公式换算部件中心偏移与
  尺寸；槽位顺序按 `mDepth`；`mColor` 与 `mIsActive` 保留用于动画；
- `.anim` → Spine 时间线：四元数旋转曲线按 0.05s 栅格采样转 z 角写 `rotate`，
  位移曲线同栅格求 Hermite 值写 `translate`；`m_IsActive` → 槽位 attachment
  timeline，`mColor.*` → 槽位 color timeline；
- 图集重打包：只收集当前服装实际用到的裁切块，shelf 贪心打包到尽量少的 2 的幂
  尺寸页。

已修正的坑：

1. `.atlas` 页头与 region 之间不能有空行；format 需大写 `RGBA8888`；
2. 该 3.8 渲染管线里 `.atlas` 的 `xy` 是左上原点，不能做 y 翻转；
3. 旧 Spine380 绑定在 C++ `RangeBuffer()` 有越界/释放问题，需用修复版 pyd
   （本项目只负责输出数据；Viewer/Render 需自行升级绑定）。

## 4. 使用方法（NGUI 路线）

环境：Python 3.10+、Pillow、Unity 工程 Assets 目录（默认
`D:\VB\Search\BdOne\Assets`）。

图形界面（推荐）：`python gui.py` 或双击 `run_gui.bat`。流程：选 Assets 目录
→ 选角色 prefab → 设输出目录 → 采样间隔 0.05 → 勾选自动结构校验 → 转换。

```text
输出目录/
└── 角色名/
    ├── 角色名_00_服装A.json / .atlas / *_atlas_00.png
    ├── 角色名_01_服装B.json / ...
    └── convert_summary.csv
```

命令行：`python run_cli.py "<prefab>" output 0.05`

与 Unity 真值比对：

1. 用 `tools/unity_validation/UnityAnimationExporter.cs` 在 Play Mode 逐 clip
   导出原 Transform 帧 JSON（`角色名_clip名.json`）；
2. Spine 侧同名骨骼的 setup + 时间线增量换算成同一时刻局部值；
3. 对比 `localPosition` 与 `rotationZ`：位置差 < 1e-3、角度差 < 0.1°；
4. 需要整帧画面比较时用离线 Render 出 PNG 肉眼核对。

参考源码位置：

- 转换器核心：`D:\VB\Unity2Spine\ngui2spine\`
- 原始工程：`D:\VB\Search\BdOne`（NGUI + Legacy Animation + spine-unity）
- 参考运行时：`D:\VB\Search\spine-runtimes-3.8`（官方 3.8）
- 离线渲染器：`D:\VB\Viewer\Render`

## 5. 多 Spine 合并

### 5.1 转换产物（NGUI → Spine）的合并

`ngui2spine/merge_char.py` 处理"一个 prefab 里有多个带 Legacy Animation 的
子装配"（如 BdOne `阿波罗` = `协助(Helper154)` + `原皮(Npc258)`）：

```bash
python -m ngui2spine.merge_char "D:\VB\Search\BdOne\Assets\prefab\chr\阿波罗.prefab" 输出目录
```

规则：每个子装配独立转 Spine 后挂到一个新增 `Root` 骨骼下；保留各子装配根的
本地变换；槽位按 `mDepth` 全局排序；图集页合并进同一 `.atlas`；动画保留各自
clip 并额外生成 `combined`。

### 5.2 直接由多个 SkeletonAnimation 组合的 prefab

`法兰.prefab`、`伊斯丽洛克.prefab` 是"现有 Spine 二进制 + SkeletonAnimation
拼装"。`ngui2spine/extract_unity_spine.py` 可先把 Unity 布局导出成清单 JSON
（本地位置、翻转、动画名、scale、skel/atlas 路径）：

```bash
python -m ngui2spine.extract_unity_spine "…\法兰.prefab" 布局.json
```

两种合并方式共用同一核心（`merge_existing_spine.py`）：

- **方式 A 直接合并（读 `.skel`）**：`spine38_binary.py` 依据官方 spine-cpp 3.8
  `SkeletonBinary.cpp` 解码二进制骨架，不产生中间 json；
  `--mode direct --skel`
- **方式 B 先转 JSON 再合并**：借 `third_party/SpineSkeletonDataConverter.exe`
  把 `.skel` 转成可见 JSON；`--mode json --skel`

合并产物写 `.skel` 时（`--skel`）默认用本项目原生写出器
（`ngui2spine/spine38_binary_writer.py`，见 `静态prefab路线.md` 9.3），失败才
退回第三方转换器；顺序口径用 `--skel-writer auto|python|exe` 控制。

GUI：`gui.py` 的"多 Spine 合成"栏，选 prefab + `direct`/`json` + 是否输出
`.skel`，点"合并当前角色"。

> 所有 Spine 产物（含合并产物、单帧产物）在输出目录里都会同时写一份
> `.config.json`，查看器/编辑器可直接打开该目录。schema 与刷新方法见
> `静态prefab路线.md` 第 9.1 节，批量补写用
> `python tools\refresh_viewer_config.py <目录>`。

### 5.3 合并规则与输出

```text
每个子节点 = 一个 SkeletonAnimation
  -> 新增 Root + mount_<子装配> 骨骼（保留 Unity 根变换/翻转/动画设置）
  -> 子装配内骨骼/槽/约束/附件按需前缀化，避免重名
  -> 默认皮肤附件合并；子装配图集页按序并入同一 .atlas

输出：<角色>_合并.json / .skel / .atlas / .png(_0/_1...) / _merge_info.json
```

动画：每个子 Spine 的动画保留为 `<装配>_<动画名>`；额外生成 `combined`，
按各 SkeletonAnimation 的 `animationName` 与 `timeScale` 烘焙成真实时间。

### 5.4 已验证与限制

- direct 与 json 两种模式的合并骨架：骨骼/槽/皮肤附件数量与命名一致；
- 同一合并数据的 `.json` 与 `.skel` 用离线 Render 渲染逐像素一致（法兰 0 差异）；
- 合并出的 `.skel` 与第三方转换器输出**逐字节一致**（法兰 286KB / 伊斯丽洛克
  268KB，2026-09-12 用 `tools\check_skel.py --ref-exe` 复核）；
- 2026-09-12 修掉读回器的 `hull` 位移 bug：3.8 二进制里 mesh 的 `hull` 就是
  JSON 的顶点个数（spine-csharp 读时 `<<1`），原来读回时多右移一位，导致
  direct 模式的合并产物 120 个 mesh 的 hull 只有真值的一半
  （`skin147_eye1_2` 4 → 9）；用游戏里原始 Spine 编辑器导出的
  `skin133.skel.bytes`（hull 57/14/16/5）对齐验证；
  （仓库里现成的 `samples\多Spine合并\*.json/.skel` 是修复前生成的，hull 仍是
  一半；重跑一次 `--mode direct --skel` 即可得到正确 hull，其余字段不变）；
- 样例：`samples\多Spine合并\法兰`、`samples\多Spine合并\伊斯丽洛克`；
- 限制：两个子 Spine 的槽位按 prefab 子节点顺序整段堆叠（需要交错时请调整
  prefab 顺序）；子 Spine 自带 drawOrder 时间线不叠加（两个样例都无）；
  Unity `initialFlipX/Y` 用 mount 骨骼负 scale 等价表达，同时有旋转和翻转时
  需人工核对。

### 5.5 NormalLocal 工程的 Spine 4.1 多皮肤组合

`D:\VB\Search\NormalLocal\lastOrign` 里更常见的是多个 SkeletonAnimation 引用
**同一个骨架 JSON（4.1.x）**，用 `initialSkinName` 分皮肤叠放（face/body/
breast/background 等层）。合并器据此处理：每个子装配保留完整骨架副本、
按 `initialSkinName` 选默认显示槽、加权顶点插入 Root/mount 后自动平移骨骼索引、
支持 mesh/region/path/linkedmesh、槽 `blend`（4.x）与约束/4.x attachments 时间线
同步改名。

测试结果（只做结构/数值校验）：多 SkeletonAnimation prefab 20 个全部可合并、
结构自检 20/20 通过；离线 Render 抽样 17/20 成功。待排查：dione_normal /
dione_skin1（json→skel 与合并结果会让 Spine 绑定段错误）、
snowfeather_skin2_mod（single 首动画空白）。

NormalLocal 主目录（`0test`、`rawLo/*/2DModel*`）是 SpriteRenderer + Mesh 的
自有 2D 模型，不属于 NGUI/Spine 管线——那部分见 `静态prefab路线.md`。

## 6. 2DModel 帧烘焙路线（历史）

目标：把 `SpriteRenderer + SkinnedMeshRenderer/MeshRenderer + Animator` 的
2DModel prefab 转成 Spine，并保证立绘与动画与 Unity 基本一致。

走过的失败路线：

1. **纯离线解析骨骼**：能还原"骨架层"，但很多角色拆成散件/错位，坐标与绑定
   顺序全靠猜；
2. **Unity 真值锚定**（t=0 BakeMesh + bindposes + sprite corners）：skinned 层
   接近 Unity，但多角色仍缺静态底图/头部 sprite 层或叠加错位；
3. **仿射/UV 配准**：局部看似完整，vision 复核发现肢体扭曲。

当前（历史）路线 = **帧烘焙**：不是只定骨骼，而是恢复每一帧的画面顶点。

Unity 侧脚本：

- `TwoDModelDebugExporter.cs`（runtime，挂动画根进 Play Mode）：按 Animator
  状态与 0.05s 步长密集采样，每帧导出全部 Transform、每个 SkinnedMeshRenderer
  的 `BakeMesh` 顶点/uv/三角形、每帧 `localToWorld`、每个 SpriteRenderer 的
  `localCorners/worldCorners` → `info/Data/PoseFrames/<场景根名>.json`；
- `TwoDModelUnityExport.ExportAll`：t=0 精确真值；
- `TwoDModelSceneLayoutExporter.Export`：相机/子树/世界包围盒。

转换侧 `ngui2spine/frame_baked.py`：读 PoseFrames → 每帧
`worldPoint = localToWorld * BakeMeshLocalVertex` → 第 0 帧作 setup、后续帧作
deform 偏移 → sprite 用每帧 worldCorners 直接放置 → 输出 Spine json/atlas。

结果与结局：aeda 用它完成过 `samples/2DModel/aeda/anim_v2`（323 帧/16.1s，
43 部件）并通过 vision 认证，但该路线**依赖 Unity 运行态导出**，不符合"只用
磁盘静态资源"的要求，现已被 `静态prefab路线.md` 取代（细节与修复记录见
`报告与校验.md` 第四节）。
