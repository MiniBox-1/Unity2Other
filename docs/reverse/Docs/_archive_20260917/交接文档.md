## 0. 30 秒版

把 Unity 里的 2DModel 动态立绘（`SpriteRenderer` + `SkinnedMeshRenderer` +
`Animator`）**离线**转成 Spine 3.8（json / atlas / png，`--skel` 时另出
同数据的 `.skel` 二进制）。

- 骨架只有 `Root`，每个部件一个 mesh attachment，动画是逐帧顶点写进 `deform`；
- 状态：**已可用、有量化验收**。三个主力角色逐顶点误差 ≤ 0.00001 世界单位；
  50 角色泛用性 A 42 / B 3 / C 3 / D 0（平均 0.0252，最大 0.281）；
- 产物：`samples/2DModel/<角色>/static_spine[_pma]`；
- 唯一硬约束：**Unity 运行态导出的真值只用于校准，不能进成品**。

## 5. 一次完整工作流（导出 → 四层校验）

```bat
:: ① 导出（静态检查自动跑）
python -m ngui2spine.static_prefab_spine <prefab> <out> --assets <Assets> --scene <save.unity> --calib
::    加 --skel 会再写一份同数据的 Spine 3.8 二进制骨架 <角色>_static.skel

:: ② 静态检查（也可单独跑）
python tools\static_check.py <prefab> --scene <save.unity> --spine-dir <out>

:: ②b 二进制产物校验（可选；--convert 由 json 生成 skel，--ref-exe 再与转换器逐字节对拍）
python tools\check_skel.py <out> --convert --ref-exe

:: ③ 逐顶点几何校准（单个 / 批量）
python tools\calib_geo.py --prefab <prefab> --assets <Assets> --scene <save.unity> ^
  --only-spine-dir --spine-dir <out> --times 0,1,2,3,4 --pose <PoseFrames\角色.json>
python tools\calib_geo_batch.py --spine-root <产物根> --jobs 4 --json <报告.json>

:: ④ 图像级（轮廓 IoU / 光晕层 / 单脸）
python tools\compare_frames.py --spine-root <产物根> --frames-root <info\Data\Frames>
python tools\calib_full.py    <out> --ref <Frames\角色\00_full.png>
python tools\calib_sprites.py <out> --ref <Frames\角色\03_sprites_dark.png> --bg 10,10,10,255
python tools\face_check.py    <out>          :: 截单脸 + vision.js（结果在 <out>\_face_check\）
```

四层判据：结构四项计数全 0 → 逐顶点误差 ≤0.05 世界单位（A 档）→ 轮廓 IoU ≥0.97 →
vision 复核“方向/数量/颜色一致”。

## 6. 硬性规则（别违反）

1. 导出只允许用**磁盘静态资源**（prefab / .unity / Mesh / Material / Sprite /
   .anim / AnimatorController）；
2. `PoseFrames` / `Frames` / `SceneT0` / `StaticMeta` 等运行态导出**只用于校准**，
   绝不能参与成品生成；
3. 部件朝向只能由**世界矩阵**决定，禁止按名字硬编码翻转/镜像；
4. 任何图片结论都要用 `node D:\VB\vision.js <图> "<问题>"` 得出，不要凭图名猜；
5. 每次转换后跑静态检查；建议带 `--calib`；
6. 渲染/输出尺寸按源图 1:1，不做额外缩放（坐标默认就是源图像素）；
7. 动手前读 `D:\VB\询问前规则.md`；
8. 删除/覆盖前先确认目标（产物可重跑，Unity 工程里的资源不要乱动）。

## 7. 排障手册（症状 → 去哪查）

| 症状 | 先看 |
| --- | --- |
| 导出直接报 `没有可用 AnimatorClip` | 主 Animator 选错 → 路线文档 **3.12** |
| 面罩/某个部件方向错、镜像反复变 | TRS 缩放顺序 → **3.1**（禁止按名字翻转） |
| 动画里部件飞散 / 与骨骼脱开 | blend 索引存放方式 **3.2**、null 骨骼占位 **3.4** |
| 某部件静止时就固定偏移 | 无权重通道的小网格 **3.9**；或“全局平移” **3.14** |
| 光晕/特效整段不见 | 退化误删 **3.6**、副 Animator rest 表 **3.8** |
| 光晕偏暗/偏白、颜色不对 | Alpha 与 Shader 约定 **第 6 节**（Unity 用 `--pma` 产物） |
| 静态检查报“曲线 path 对不上 N 条” | 折行 path **3.3**、宿主截断 **3.13**；指向另一个 Animator 子树属正常 |
| 导出的部件比场景少 | `--animated-only` 排除了静态立绘（audrey 属正常）；或回退分支 **3.14** |
| 图集出现两张 | **第 5 节**（加色区与普通混合共用像素时才需要） |
| 角色被放大数倍 / 尺寸怪 | 宿主名截断 **3.13**、单位 **9.2**（`--units px`） |
| 眨眼/表情过渡僵硬、闪烁 | 关键帧对齐与瞬切 **3.11**、SetActive 表情切换 **3.10** |

调试顺序建议：**静态检查 → 逐顶点 → 图像 IoU → vision**，一层不过就别看下一层。

## 2026-09-14 更新（副 Animator 显隐修复 + 产物现状）

### 这一轮修的关键 bug

**带副 Animator 的角色，特效部件的显隐整条丢失。**

AnimatorClip 的曲线 `path:` 是相对**该 Animator 所在物体**的。副 Animator（daphne 的
左右翅膀、aeda 的 `star_deco`、babariana 的 `Bg_Only`）的曲线路径相对它自己，而转换器
只按**主 Animator** 归一化 `anim_path`，于是 `active_curves.get(anim_path)` 永远不中
→ 这些部件被判"所有动画里都不可见" → 直接丢进 `excludedParts`（理由写成"Unity 里
始终禁用"，是**假理由**）。

修法（`ngui2spine/static_prefab_spine.py`）：

- `_curve_lookup(curves, anim_path, prefix)`：先精确查；查不到就把 `anim_path` 去掉
  `prefix`（该 Animator 相对主根的路径）再查
- `enumerate_clips()` 给每条 entry 的 clip 挂 `_prefix`；**同一 clip 被多个 Animator
  引用时必须 `dict(clip)` 复制**，否则左右翅膀互相覆盖
- `node_visible()` / `part_visible()` 带上 `_prefix`。主 Animator 前缀为空 → 行为不变

> ⚠️ **不要用全局后缀匹配兜底**。第一版那样写过：链上不该命中曲线的祖先也命中，
> `node_visible()` 里"整条链从头 inactive 就当场景摆放"的逃生口被误触发，显隐**极性
> 反转**（左翼曾输出 `0 显示 → 1.35 隐藏 → 2.5667 显示`，而曲线是
> `(0,0)(1.0667,1)(2.7833,1)(2.8,0)`）。

效果：daphne `3P_Daphne_FX` 的 slot 时间轴 **6 → 123**；全量重转 50 个后显隐校验
从 43/50 提升到 **50/50**（详见 `docs\副Animator显隐修复.md`）。

用户要求（`_probe50_rt2/Question/qustion.txt`）：**把所有 RenderOrder 的渲染改为
计算相对层级；一个组件的相对层级老是变化，就分配多个 drawable，启用哪个层级用哪个。**

> **同日追加的三条决定（工作方式，先按这个来）**
>
> 1. **先不要多 drawable** —— `--multi-drawable` **默认关闭**，导出仍是
>    "一部件一槽位 + 静态 sortingOrder 顺序"；`relative_layers()` 只当**诊断量**
>    用（`_static_info.json.relativeLayers` 会列出"要是启用会变层"的部件）。
>    原因：一个部件要 N 层就要把同一份逐帧形变写 N 遍，draculina 会膨胀到 GB 级。
> 2. **不做批量重转** —— 一个角色一个角色地修（改代码 → 只转这个角色 → 对账）。
>    `_probe50_rt3/` 只覆盖 `qustion.txt` 点名的 16 个角色，不是新的全量基线。

>    是我们产物的缺陷；**用"动态属性查看"校准**（见下一小节）。

已完成：

1. `ngui2spine/static_prefab_spine.py` 里落地 **相对层级**：
   `relative_layers()`（重叠邻居内的相对次序）→ `expand_layers()`（按"部件 × 层级"
   展开 drawable）→ `layer_at()`（阶梯函数二分，查"这一刻该亮哪个 drawable"）；

## 2026-09-15 下午更新（修掉"两张脸"的根因 + 16 个点名角色重转）

### 这一轮修了什么

**Sprite 交换（换表情/换贴图）的变体附件没有 deform 时间线。**

- 现象：`constantias2_skin1` breast 里角色的脸裂成两张，一张跟着身体动、
  另一张停在原地（`qustion.txt`："breast 两张完整脸，在运动时一张不变一张清晰可见"）。
- 根因：`m_Sprite`（PPtr）交换导出成"一个 slot 多 attachment + attachment 时间轴"
  （主文档 3.10）；而 Spine 3.8 的 `deform` 时间线路径是 `slot/attachment`，
  **只在"当前挂的附件 == 时间线绑定的附件"时生效**。只把形变写在基础附件名
  （`face_ani_21`）下，动画切到 `face_ani_21__2 / __3` 的那段时间形变整段失效
  ⇒ 部件冻在初始姿势 ⇒ 看起来像两张脸。
- 修法：`ngui2spine/static_prefab_spine.py` 建槽位时记录 `variants_by_slot`
  （该 slot 的交换变体附件名，只收顶点数一致的），写 deform 时**给每个变体附件名
  各写一份同一份关键帧**。
- 定位手法（值得复用）：几何比对 0.00000、显隐比对逐帧全对之后，**把可疑槽位的
  `attachment` 置空单独渲染**，再用查看器的 Spine 3.8 运行时 dump 每帧 VBO，
  看那一组顶点是否跟着动 —— 一眼就能分出"几何错 / 显隐错 / 根本没被驱动"。

完整现象 → 根因 → 修法 → 验证数字见 `静态prefab路线.md` **3.23**。

**硬规矩（写进流程，别人接手也照做）**

1. **不量内存不许并行**：每件重活先用新工具 `tools/mem_probe.ps1` 量峰值
   （它会连**子进程**一起数，超过 `-LimitMB` 直接杀，保护整机），
   同时跑的**峰值之和 ≤ 10 GB**（本机物理内存 15.8 GB）。
2. **大产物必须带 `.skel`**：`python tools\write_all_skel.py <产物根>`。
   否则渲染器会去读大 JSON，单帧就能吃 10 GB+。
3. `convert_all_2dmodel.py` 的 `--jobs` 是内存乘数（最重角色 1.26 GB/个）：
   大角色只开 `--jobs 1~2`。
4. Unity 批处理（`ModelInspect.All` 1.84 GB）同时只跑一个，**绝不**和渲染/批量转换并行。
