## 1. 显隐与属性写入（曲线 → 场景）

| 转换器逻辑 | 汇编依据 | 结论 |
| --- | --- | --- |
| `m_IsActive` 曲线 → 部件显隐 | `AnimationBinder::CalculateTargetPtr`（`0x180B40540`）：`GameObject` + `"m_IsActive"` ⇒ **type 7**，目标指针 = GameObject 本体；`Animation::SetBoundCurveFloatValue`（`0x180B39180`）case 7 ⇒ `GameObject::Activate()` / `Deactivate()`，判据 **`\|v\| > 0.001`** | ✅ 一致（转换器 `active_is_on()` 就是 `abs(v) > 1e-3`；旧实现用 `v≥0.5` 是错的，已修） |
| `m_Enabled` 曲线 → 渲染器开关 | 同一个函数 **case 6**（bool）：`v>0.001 \|\| v<-0.001` ⇒ 写 1，否则 0 | ✅ 一致 |
| float 属性（顶点色分量等） | 同函数 **case 5**：直接写 float | ✅ 一致 |
| int 属性（`m_SortingOrder`） | 同函数 **case 10**：`v+0.5`，负数再 `-0.99999994`，向零截断 | ✅ 一致（`unity_int_round()`；实测 `0.5→1 / -0.5→0 / -2.5→-2`） |
| 材质属性（`material._Color` 等） | 同函数 **case 14/15/16**（`Material::SetFloat` / `SetVector`） | ✅ 一致（`_Color` 走 slot 颜色时间轴；`_AdditionalAlpha` 等自定义 shader 属性不导，见第 5 节） |
| `m_Sprite` 换图 | `Animation::SetGenericPPtrPropertyValues`（`0x180B44D70`）：**直接写引用**（`gc_wbarrier_set_field` / 原生 PPtr），**没有任何插值** | ✅ 一致（换图按阶跃处理；同 slot 多 attachment + 时间轴） |

## 2. 变换、旋转与曲线求值

| 转换器逻辑 | 汇编依据 | 结论 |
| --- | --- | --- |
| 曲线求值是 Hermite（用关键帧的 in/out slope） | 无加权切线（数据里 `weightedMode` 全 0）；实测：`(0,0)→(1,1)` 斜率 0 的曲线，`\|v\|>0.001` 的开启时刻 = **0.019**，而 `3u²−2u³=0.001` 的解是 0.01826 —— 逐点吻合 | ✅ 一致（`unity_curve_eval()`） |
| 欧拉 → 四元数的顺序 | `math::EulerToQuaternion(Vector3f, RotationOrder)`（`0x180587F20`）由**数据字段**决定顺序（`mov r8d,[rdi+28h]`）；工程里 73011 条 `m_EulerCurves` 全部 `m_RotationOrder: 4` = **ZXY** | ✅ 一致（`euler_to_quat()` 就是 `qy⊗qx⊗qz`） |
| 同一对象同时有四元数与欧拉曲线时用哪条 | 运行时姿态（`trsX` / `SkeletonPoseT`）的旋转通道是**四元数**；`TransformValuesFromClip`（`0x180BAB720`）把 clip 值写进 16 字节的四元数槽 | ✅ 一致（采样器"有 rot 就忽略 euler"；实测 bheur `Bone_Pelvis` 真值 3.878/1.045/4.458 只与四元数吻合） |
| 局部 TRS → 世界矩阵、Sprite 四角（rect/pivot/ppu） | 没有逐条读汇编（属于渲染几何）；**用真值实测**：三主力逐顶点 **0.00000 / 0.00001**，sprite 与世界 AABB 完全重合 | ✅ 实测一致 |

## 3. 蒙皮与形变

| 转换器逻辑 | 汇编依据 | 结论 |
| --- | --- | --- |
| 蒙皮 = Σ 权重 × 骨骼矩阵 | `CombineBoneSkinning`（`0x1804D7FA0`）用 `BoneWeights4`（每顶点 4 组权重）；`SkinnedMeshRenderer::BakeMesh`（`0x1804FD460`）→ `SkinMeshCPU`（`0x18050C100`） | ✅ 一致 |
| blendShape **先于**蒙皮 | `ApplyBlendShapesToVertices`（`0x1804F45F0`）在 skinning 之前把形变加到局部顶点 | ✅ 一致（`morph_positions()` 在 `_skin_mesh` 之前改 `positions`） |
| blendShape 权重语义 | `BlendshapePropertyBinding::SetFloatValue`（`0x18050AF20`）→ `SkinnedMeshRenderer::SetBlendShapeWeight`（`0x1804FE270`）；`CalculateBlendShapeWeights`（`0x1804F42E0`）：`factor = weight / thr[帧]`，多帧时 `v=(w−thr[k])/(thr[k+1]−thr[k])` 输出 `(1−v, v)` 两帧权重 | ✅ **已按汇编修正**：`fullWeights` 是**按帧**的阈值；原来 `w/100×fullWeight/100` + 按帧序号插值是错的。修后 bheur breast 逐顶点 **0.025 → 0.0054** |
| `m_Shapes` 的多帧形变 | 同上（阈值形如 `[25,50,75,100]`，甚至非单调的 `[100,50,100]`，数据里 44 条） | ✅ 一致（按阈值在权重空间插值） |

## 4. 动画层（Animator 多层）

| 转换器逻辑 | 汇编依据 | 结论 |
| --- | --- | --- |
| 加性层的**参考姿态** | `mecanim::animation::InitClipMuscleAdditivePose`（`0x18139CF70`）：参考 = `EvaluateClip(clip, time)`；调用点 `AnimationClip::GenerateMuscleClip`（`0x1813A28A6`）传的是 clip 的 `m_AdditiveReferencePoseTime` | ✅ 一致：**全库 27 个带该字段的 clip 都是 `has=0 / time=0`** ⇒ 参考 = 自身 t=0 的姿态 |
| 加性层混合公式 | `DeltasFromClip<0>`（`0x180BB1480`）算"clip − 参考"；`TransformValueArrayAdd`（`0x180BBB770`）按层权重加到已有结果 | ✅ 一致（`v = base + (over − over(0))`） |
| 层短于主 clip 时循环 | 状态机语义 + 实测（4.33s 的增量 = 1.0s 的增量，周期 = clip 时长） | ✅ 一致（按自身时长复制关键帧） |
| Override / Additive 的模式值 | 控制器 YAML `m_BlendingMode`：0=Override、1=Additive；运行时由 `AnimationLayerMixerPlayable`（`0x180BA32A0` 等）混合 | ✅ 一致 |
| **加性层的旋转用四元数乘**（不是欧拉相加） | `TransformValueArrayAdd` 的旋转分支是**四元数乘**（分量乘 + 混洗），`trsX` 的旋转通道就是四元数 | ⚠️ **单轴等价**：本项目所有加性层都只绕 Z 轴，两种算法结果相同（实测 bheur 与真值一致）；**多轴**加性层要把 `compose_layers` 的旋转分支改成四元数乘（已记入遗留） |

## 5. 其它 / 未导出的通道

| 项 | 依据 | 状态 |
| --- | --- | --- |
| Write Defaults 的"默认值"来自哪里 | `Animator::CreateBackupDefaultValues`（`0x180B64880`）= 把 Animator **当前姿态**备份一份；`WriteDefaultValuesNoDirty`（`0x180B62DD0`）再写回去 | ✅ 一致：没被 clip 动画的属性回落到 **prefab/场景的静态值**（`--scene` 用来取场景姿态） |
| `material._AdditionalAlpha` 等自定义 shader 属性 | 语义依赖 shader（不是简单 alpha 相乘） | ❌ 不导出，每个角色在 `_static_info.json.unsupportedChannels` 里列出 |
| `m_SortingOrder` 整体重排（draculina 手部） | Spine 的 drawOrder 偏移只能非负（`SkeletonBinary` 用 unsigned varint），无法表达任意置换 | ❌ 整条不导（沿用静态顺序），见 `已知问题.md` 第 2 条 |

## 6. 复现方法

```bat
:: 反汇编查询（一次加载可跑多条；REQ_INLINE 也可以是请求数组）
copy D:\Reverse\win64_player_nondevelopment_il2cpp\UnityPlayer.dll.i64 _reverse\UP.i64
set REQ_INLINE={"op":"decompile","ea":"0x180B39180"}
set REQ_OUT=_reverse\res.json
D:\Reverse\IDA_Pro_v8.3_Portable\idat64.exe -A -L_reverse\ida.log ^
  -S"D:\VB\Unity2Spine\tools\ida_q.py" _reverse\UP.i64

:: 行为实测（同版本 2022.3.3f1c1，隔离工程）
set PROBE_OUT=D:\VB\Unity2Spine\_reverse\unity_probe_result.json
D:\Unity\Editor\2022.3.3f1c1\Editor\Unity.exe -batchmode -nographics ^
  -projectPath D:\VB\Unity2Spine\_verify_animator -executeMethod AnimProbe.Run ^
  -logFile D:\VB\Unity2Spine\_reverse\unity_probe.log

:: 产物侧的量化验证
python tools\static_check.py <prefab> --scene <save.unity> --spine-dir <产物>
python tools\calib_geo.py --only-spine-dir --spine-dir <产物> --pose <真值.json> --times 0,0.6,1,2,3,4
python tools\compare_play_truth.py <产物.json> <PlayFrames\…json> <状态名>
python tools\check_clip_visibility.py --spine-root <产物根> <角色…>
python tools\check_skel.py <产物目录> --ref-exe
python tools\audit_playframes.py
```

> `_reverse\` 是一次性目录（IDA 库副本 468MB、请求/结果 JSON），核对完可整个删掉；
> 需要再核对时按上面的命令重建。`_verify_animator\` 是那套 Unity 实验工程（5MB），
> 留着复现"行为实测"。

## 7. 一句话结论

**转换逻辑已与汇编核对完毕**：显隐判据、各类型属性的写入语义、PPtr 换图、
blendShape 权重公式、动画层的参考姿态与混合公式、欧拉顺序、Write Defaults 的
来源 —— 都能在反汇编里找到对应实现；不能直接读汇编的几何/蒙皮部分，用真值
逐顶点比对到 **0.00000~0.0054 世界单位**、可见性逐格 **0 差异**、
`.skel` 与第三方转换器**逐字节一致**。

只剩两条**明确登记**的（不是"没核对"，是"运行时行为本身不好表达/不该导"）：
加性层的**多轴**旋转要改成四元数乘；自定义 shader 属性与 draculina 手部重排不导。
