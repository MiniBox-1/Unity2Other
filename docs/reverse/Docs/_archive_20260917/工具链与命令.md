## 0.5 内存：**一次只跑一件重活**（2026-09-16 夜实测）

本机物理内存只有 **15.8 GB**，而"看图"这条链是**内存黑洞**。实测（`PeakWorkingSet64`，
子进程一起数；渲染器 `python.exe` 是 venv 启动器，真正的 worker 是它的子进程，
**只盯启动器会看到一个 11 MB 的假数字**）：

| 动作 | 峰值内存 | 用时 |
| --- | --- | --- |
| **`tools/rt_frames.py` 走 JSON 路径 + 大产物**：`draculina_skin1`（JSON 245 MB） | **>11.6 GB**（拉到 11 GB 阈值被 `mem_probe` 杀掉，还在涨） | 55 s 内 |
| **同上**：`alice_skin1_fix`（JSON 117 MB） | **>8.1 GB**（8 GB 阈值被杀） | 51 s 内 |
| **同一份产物、但存在 `.skel`（查看器优先读它）**：`draculina_skin1` 5 帧 | **0.77 GB** | 13 s |
| `tools/rt_frames.py`（`banshee_skin1`，有 `.skel`，1 帧 900） | 0.63 GB | 14 s |
| **单角色转换（最重一档）**：`draculina_skin1` | **1.26 GB** | 284 s |
| 单角色转换：`audrey_skin1` | 0.36 GB | 29 s |
| `tools/convert_all_2dmodel.py --jobs 2`（两个小角色） | 0.44 GB（父进程只有 39 MB） | 36 s |
| `tools/check_play_visibility.py`（1 角色） | 0.56 GB | 11 s |
| `_scratch/q2_part_geom.py`（1 角色 × 1 帧，读 40 MB PoseFrames） | 0.09 GB | 5 s |
| Unity `ModelInspect.All`（1 角色 2 帧，`-probePpu 320`） | 1.84 GB | 169 s |

**2026-09-17 复测（新增结论）**：13 GB 那一档的**真凶是"渲染器读 JSON"这条路**+
**大产物**；同一份产物只要 `.skel` 在（查看器优先选二进制），峰值掉到 **0.6~0.8 GB**。
所以"渲小一点"依旧救不了内存（峰值与画布尺寸无关），但"**保证大产物有 `.skel`**"能救。

**结论 / 硬规矩**：

1. **不量内存不许并行**：每件重活先用 `tools/mem_probe.ps1` 量出峰值，
   把"同时跑的峰值之和"控制在 **≤ 10 GB**（15.8 GB 物理内存要留余量给系统/编辑器）。
2. **渲染 `rt_frames.py`**：
   - 大产物**必须带 `.skel`**（`python tools\write_all_skel.py <产物根>`），
     否则单帧就可能 >10 GB；
   - 即便如此，也**不要**和 Unity 批处理、批量转换同时跑（0.8 + 1.8 + 0.7 已接近 4 GB，
     一旦碰上 JSON 路径就直接爆）。
3. `convert_all_2dmodel.py` 每个角色起一个子进程，**`--jobs` 就是内存乘数**
   （最重角色 1.26 GB/个 ⇒ `--jobs 2` 最坏 2.5 GB，`--jobs 4` 最坏 5 GB）。
   跑大角色时**只用 `--jobs 1~2`**。
4. Unity `ModelInspect.All` ≈ 1.84 GB/进程，**同时只跑一个**。
5. 量内存的写法（PowerShell，别只看父进程）——已封装成工具：

   ```powershell
   # 量一条命令的"进程树"峰值；超过 -LimitMB 直接杀，保护整机
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\mem_probe.ps1 `
     -Exe "D:\VB\Viewer\Render\.venv\Scripts\python.exe" `
     -ArgList "tools\rt_frames.py|_probe50_rt4\banshee_skin1|lobby|--out|_scratch\_x|--times|0|--size|900" `
     -LimitMB 8000
   ```

   > 为什么必须连子进程一起数：渲染器的 `python.exe` 只是 venv 启动器（11 MB），
   > 真正的 worker 是子进程；只看启动器会得到假数字。

### 1.4 坑（都踩过）

1. **别在原始 `.i64` 上跑**（IDB 会被改写）：先拷一份，本仓库统一放 `_reverse/`。
2. **`-A -c -o<file>` 这套会立刻 `exit=1`**；`-h` 会**挂住**（弹对话框）。
   能用的组合只有 **`-B -S<script> -L<log> <dll>`**（建库）与
   **`-A -S<script> -L<log> <i64>`**（查询）。
3. **IDA 是在输入名后面追加 `.i64`**：`UP2022.dll` → `UP2022.dll.i64`
   （不是把 `.dll` 换成 `.i64`）。
4. **符号地址常是跳转桩**：`decompile` 只出 `JUMPOUT(0x...C923)`，真身在其后
   3 字节 ⇒ 用 **`ea+3`** 再查。
5. PDB 必须与 DLL **同目录、且用 PDB 里记录的原文件名**
   （`UnityPlayer_Win64_player_mono_x64.pdb`），否则符号加载不上。
6. 查完把 `idat64` 收掉（`Get-Process idat64 | Stop-Process -Force`），免得占内存。

## 2. Unity 编辑器：批处理导数据 / 渲染

### 2.0 ⭐ 参考帧（Play 模式 + 相机）：`Assets/Editor/PlayRefShot.cs`（2026-09-17 新增）

```text
菜单：Tools/2DModel/运行时采样/参考帧（带相机）…
填：  角色名（逗号分隔，空=场景里所有 2DModel）
      状态名（逗号分隔，空=该 Animator 的所有状态）
      时刻/秒（逗号分隔，**是秒，不是归一化比例**）
      ppu（像素/世界单位，默认 640）、取景留白 margin（默认 1.08）
      是否写网格顶点（几何对账用，文件会大）
点：「开始（自动进 Play 模式）」→ 采完自动退出 Play（可关）
日志：D:\VB\Unity2Spine\info\_logs\play_sample.log
输出：info\_refshot_<角色>\
        frames\<角色>__<状态>__t<毫秒>.png      带相机的渲染帧
        frames\<角色>__<状态>__t<毫秒>_cam.txt  cx/cy/size/aspect/w/h/ppu（与 _inspect_* 同格式）
        <角色>__<状态>__t<毫秒>.json            同帧逐渲染器数据
```

**为什么必须 Play 模式**：`m_IsActive` / `m_Enabled` 这类曲线只有在 Animator 真跑时
才会落到 GameObject / Renderer 上。`ModelInspect`（batchmode）用编辑器采样，
**不改 `activeSelf`** —— 实测 banshee 的 `dynamic.json` 在 17 帧里
`activeSelf/activeInHierarchy/enabled` **0 次变化**，所以它只能当"静态姿态 + 渲染图"。

JSON 里每个渲染器一条，重点字段：

| 字段 | 用途 |
| --- | --- |
| `activeSelf` / `activeInHierarchy` / `enabled` | 这个件到底该不该出现（**显隐真值**） |
| `isVisible` | 有相机时"在视锥里且渲染器开" |
| `sortingOrder` / `sortingLayerName` | 排序层 |
| `camDepth` | 到相机视线方向的深度 —— **同 sortingOrder 的透明件就是按它排序**（大 = 画得早 = 在下层）；用来判"谁盖谁" |
| `sprite` | `精灵名|贴图名`（判换图/换表情） |
| `boundsCenter` / `boundsSize` | 世界包围盒（与我们的 AABB 对账） |
| `mesh.verts` / `mesh.tris` | 世界坐标顶点（`BakeMesh(mesh, true)`；不带 `useScale` 的重载会缩放平方，见 3.30） |

> 步进方式与 `PlayModeSamplerRunner` 一致：`Rebind()` → `Play(hash, layer, t/时长)`
> → `Update(0)`，再等两帧（`yield return null` + `WaitForEndOfFrame`）后出图/取数。

### 2.3 坑

1. **同一个工程不能开两个 Unity 实例**：编辑器开着时批处理直接报
   `It looks like another Unity instance is running with this project open.`
   ⇒ 跑批处理前先关编辑器（`Get-Process Unity` 为空、`Temp\UnityLockfile` 不在）。
2. 用 `Start-Process -Wait -NoNewWindow`（直接 `&` 有时不等待、拿不到正确退出码）。
3. 批处理里**没有相机** ⇒ `Renderer.isVisible` 恒 `false`；要看相机可见性得用菜单跑或 Play 采样。
4. 报错看 `-logFile` 里的 `error CS`（脚本编译失败**不会**让进程非 0 退出）。
5. `-executeMethod` 名字写错 / 脚本不编译，都只在日志里体现 ⇒ 跑完先 grep 日志。
6. **`meshMin/meshMax` 的 BakeMesh 口径**（2026-09-16 修）：必须
   `smr.BakeMesh(mesh, true)`。不带 `useScale` 的重载已经把渲染器世界缩放乘进
   顶点，再乘 `localToWorldMatrix` 就是缩放平方 ⇒ 框小 |lossyScale| 倍
   （babariana 实测差 6.10~6.17 倍）。**修之前生成的 `_inspect_*` 里这两项不可信**，
   要么重跑，要么只看 `boundsCenter/boundsSize`（那两项一直是对的）。
   详见 `静态prefab路线.md` 3.30。
7. **看图的技能改回模型自身多模态**（2026-09-16 用户指示）：不再走
   `D:\VB\vision.js`（也遇到过接口 500），直接用 agent 的多模态读图能力判断
   （或先用 PIL 裁切/放大可疑区域再看）。

## 5. 环境 / 策略坑

1. **PowerShell 删文件经常被策略拦**（`Remove-Item` 被拒）。要删就单独一条命令、
   用**绝对路径**、先校验前缀；实在不行留给用户删。
2. 管道给 Python 传中文要先设 `PYTHONIOENCODING=utf-8`，否则脚本里的中文正则 /
   文件名会变成 `?`。
3. `idat64` / `Unity` 这类重进程跑完确认没有残留（`Get-Process`）。
4. 长任务别用 `sleep` 干等：用 `Start-Process -Wait`，或在会话里轮询输出。
